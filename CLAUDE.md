# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> **Operator-instance specifics — forkers, read this.** This repo is the source for Kyle's `slopcafe.com` deployment. A few obligations below are tied to *that specific instance*, not to the code: the remaining hard-coded `public_id`/`slug` values point at documents in Kyle's corpus on `slopcafe.com`. If you fork this and run your own deployment, treat those as *examples* — nothing in the code depends on them. (The documentation corpus USED to be the biggest such coupling; issue #4 removed it — docs are bundled and served from `/docs/<name>` on every instance, with no per-instance ids anywhere in the registry.) Same for infrastructure names: the repo ships `slopcafe`/`slopcafe-docs`/`slopcafe-meta` defaults, but the live deployment still runs on its original `agent-web-host-*` resources — `wrangler.toml` is gitignored, so the two diverge harmlessly (naming bullet). Everything else here (the architecture, the conventions, and the source-↔-`docs/` sync rules that don't mention Slopcafe) is instance-independent.

## Commands

```sh
npm run dev            # wrangler dev — uses .dev.vars + local D1/R2
```

Database (D1):

`predeploy` injects `$HOME/.cargo/bin` into PATH so `wasm-pack` resolves from a fresh shell. Rust toolchain (`rustup` + `wasm32-unknown-unknown` target + `wasm-pack`) is only required for `build:wasm`.

## Git workflow

When the operator says "commit your work" (or similar) without specifying a branch, **commit straight to `main`** — do not branch first. The operator deliberately delegates commits to the agent so the work shows up credited in the log; keep using the standard `Co-Authored-By` trailer. Still only commit/push when explicitly asked, and push only on explicit request.

## Architecture

**Single Worker, one origin.** `src/index.ts` exports `innerHandler` (exact-match route dispatch); default export wraps it in `@cloudflare/workers-oauth-provider` (`src/oauth.ts`). The OAuth wrap intercepts `/mcp` (its `apiRoute`), validates the token, populates `ctx.props.agentId`; everything else (incl. `/authorize` and the `awh_`-bearer path on `/mcp`) goes to `defaultHandler`. The inner handler is registered as both `apiHandler` and `defaultHandler` - the only difference: whether `ctx.props.agentId` is populated. Routes match `method === "GET"` literally, so `HEAD` is normalized to `GET` by `withHeadSupport` between the OAuth wrap and `innerHandler`: re-issues as `GET` (original headers - visibility/auth/`If-None-Match` gates unchanged), strips the body: `HEAD /d/:id/raw` gets the `GET`'s `text/html`/`ETag`/CSP, not the JSON `404` (issue #36); a private/missing doc still `HEAD`s as the same opaque `404`. **Full stack, outermost first: `wrapWithOAuth(withCors(withHeadSupport(innerHandler)))`.** `withCors` (`src/cors.ts`) sits INSIDE the OAuth wrap deliberately - the provider answers `/mcp`+`/token`+`/register`+`/.well-known/*` itself and already CORS-stamps them (origin-reflecting, credential-free), so wrapping outside would double-write `Access-Control-Allow-Origin`, which browsers reject outright; inside, it sees exactly the `defaultHandler` surface, i.e. the routes our allowlist can actually govern (hence `/mcp` is NOT `isCorsEligible`). It sits OUTSIDE `withHeadSupport` so CORS is the outermost of OUR layers and stamps every final response incl. the synthesized `HEAD` ones (so `HEAD` is an eligible method in its own right). **ONGOING OBLIGATION: every route added to `innerHandler` must be classified in `isCorsEligible`** - it is default-deny, so forgetting fails safe (unreachable cross-origin) but silently; a new cookie/HTML surface under `/admin/` must be added to the exclusion ahead of the `/admin/` catch-all in the same change.

**Two auth doors converge on one identity (`AwhProps` in `src/mcp-auth.ts`):**
- **Door A (OAuth 2.1 + PKCE)** - one pre-registered client per agent: bound mint `POST /admin/agents/:id/oauth-clients`; unbound mint `POST /admin/oauth-clients` (KV record, no `oauth_clients` row), agent picked at consent. DCR self-registration (`POST /register`, RFC 7591, served when `ENABLE_DCR` in `src/oauth.ts` is on; public PKCE-only clients allowed - required for native CLIs like `claude mcp add`; constants + 90-day TTL: dcr-design bullet): a DCR client arrives unbound and rides bind-or-mint - the paste-the-MCP-URL flow (dcr-design.md, BUILT). Consent UI: `src/authorize.ts`; operator approves via `OPERATOR_TOKEN` or browser session; `agentId` = the grant's `encryptedProps` via `ctx.props`. Every 302 to a client callback carries RFC 9207 `iss=<request origin>` (SEP-2468, issue #46), allow and deny alike (allow paths converge on one `completeAuthorization`), via the pure `appendIssParam` (`authorize.ts`): URL-API surgery (custom schemes + loopback parse), overwrite-if-present so a library-emitted `iss` can't duplicate (the provider does NOT emit it as of 0.8.2; pinned in `test/authorize-callback.test.mjs`); in-place HTML errors never reach the callback. Three operator-gated inline repairs (none disclose client state to non-operators): (1) **TOFU callback approval** - register an unregistered but allowlisted-host `redirect_uri` via `updateClient`; allowlist = `APPROVABLE_CALLBACK_HOSTS` (`src/admin-oauth.ts`): the narrow vendor-https TOFU list, `claude.ai`/`claude.com`/`chatgpt.com` (`validateCallbackUri` in `session.ts` = the pure https-only gate), decoupled from the consent CSP `form-action` (the old coupling blocked native clients). `form-action` = the standalone, deliberately broad `CONSENT_FORM_ACTION_SOURCES` (`authorize.ts`): `'self'`, `https:` (any vendor), loopback `http://localhost|127.0.0.1|[::1]:*` (RFC 8252), IDE schemes (`vscode:`/`cursor:`/…) - browser defense-in-depth, NOT the gate (real gate: registered-`redirect_uri` match + S256 PKCE + operator consent); add new custom schemes there (only) when onboarding. (2) **Bind-or-mint at consent** - an unbound client (no `oauth_clients` row; absence == unbound, no migration) gets a pick-or-mint-agent card; "allow" writes the binding row, then `props.agentId` is re-derived from the binding (never a form) before `completeAuthorization`. (3) **Login-from-`/authorize`** - an unauthed requester gets `/login?next=<this url>`, keyed on their own auth state. The POST ladder `authorizePostOperator` is two-rung (pasted `operator_token` -> synthetic Bearer/CSRF-exempt; else session cookie + `csrf_token` field), NOT `requireOperator` (wants an `X-CSRF-Token` header no-JS forms can't send). It and `handleRevokeForm` keep two-rung copies while `authorizeOperatorForm` grew a third rung (session paragraph) - deliberate: loosening auth on consent or irreversible revoke is an operator decision. Every consent-shaped card renders JUDGEABLE CLIENT IDENTITY (`renderClientIdentity`) - open DCR makes the consent screen the only human gate (anyone can register a client and mail an `/authorize` link - a blank card is one Allow from fleet-wide authority). Ordering is load-bearing: callback address leads (the ONLY unforgeable signal - where the code is delivered, provider-matched against registered URIs), trailing host labels emphasized, leading muted (`emphasizeHostTail`) so `claude.ai.evil.example` can't read as `claude.ai`; `clientName` = marked *self-reported claim*; then `client_id`, registration age (red under 10 min - a just-minted client reached via a link is the attack signature), client type (public/confidential - labelled, never flagged; native CLIs must be public per RFC 8252); `logoUri`/`clientUri`/`tosUri`/`policyUri` deliberately NOT rendered (phishing aid, not evidence). No per-vendor allowlist in rendering (so Claude, ChatGPT and a loopback CLI all work): `describeCallback` classifies purely by scheme + loopback-ness; the "on THIS machine" framing is reserved for `IDE_CALLBACK_SCHEMES` + exact `localhost`/`127.x`/`[::1]` - an open catch-all once rendered `evilapp://claude.ai` as a local handoff, and `*.localhost` put a familiar name in the headline. Deny button FIRST in DOM order (`flex-direction:row-reverse` restores layout) so Enter denies. The same test pins these as attacks; the two pure helpers exist solely for it.
- **Door B (static `awh_` bearer)** - same key shape as `POST /d`; plumbed into the OAuth wrap as `resolveExternalToken` so one `apiRoute` covers both transports; `agentId` from `authenticateAgent` (HMAC-under-pepper + `revoked_at` check on `agent_keys`).

**Operator browser session (`src/session.ts`) - a SECOND door onto the *operator* check, not a third agent door. The operator is separate (`authenticateOperator` = constant-time compare vs `OPERATOR_TOKEN`); the session lets them log in once (`GET/POST /login`, `/logout`, `src/login.ts`); browser-only - `/mcp` never consults these cookies, no MCP behavior changes. Stateless signed cookie, no D1/KV/migration: `awh_session = base64url({v,iat,exp,csrf}) "." HMAC(payload, signingKey)`, `signingKey = hmacSha256Hex("awh-session-signing/v"+EPOCH, OPERATOR_TOKEN)`. Derived from `OPERATOR_TOKEN` on purpose (not `HMAC_PEPPER`): rotating the token must end every session - don't "fix" this to the pepper. Two invalidation levers, both changing `signingKey`: bump `SESSION_EPOCH` (`[var]`, default `"1"`, `sessionEpoch(env)`) or rotate `OPERATOR_TOKEN`. `authenticateOperatorRequest` resolves Bearer-first then cookie**; the shared async `requireOperator` (`session.ts`; used by `admin.ts`/`admin-oauth.ts`/`DELETE /d/:id`) returns 401/403, enforcing CSRF (`403 csrf_failed`) only when authed via cookie + unsafe method; Bearer callers are CSRF-exempt - programmatic/curl unchanged.

**Operator console (`src/console.ts`, issue #22) - the server-rendered admin UI.** No-JS HTML console under `/admin/console/*` (bare `GET /admin` 302s there), authed by the operator browser session (cookie + CSRF) - logged-out gets a sign-in card, not an existence oracle. UI layer ONLY: every console POST goes through the form-field CSRF ladder (`authorizeOperatorForm`, NOT `requireOperator` - a no-JS `<form>` can't send `X-CSRF-Token`); every write reuses the `*Core` workers the JSON `/admin/*` handlers call (agent/key cores in `admin.ts`, OAuth-client cores in `admin-oauth.ts`; names in Where-things-live). **The JSON `/admin/*` API is UNCHANGED** - the `*Core` refactor kept wire bytes byte-identical. Pages: dashboard (live-doc/agent counts, a storage bar, and — issue #57 — a `countPendingPromotionCore` "pending promotion" stat linking to the review-queue preset below), agents, documents (`?q=`/`tag`/`slug`/`cursor`/`limit` core filters, a Public/Private badge, AND — issue #57 — `visibility`/`publication` `<select>`s wired straight to the same `parseHttpListParams` filters the JSON doors already parsed; `?visibility=public&publication=pending` is a one-click "Review queue" link on both this page and the dashboard, reusing `publicationClause` — exported from `core.ts` for exactly this — so the count can't drift from what the link filters to), maintenance. Minted keys/secrets show in a one-shot disclosure card (rendered once, never logged). POST-not-DELETE divergence: `POST /admin/console/agents/revoke`, `/keys/revoke`, `/oauth-clients/delete` are POST twins of `DELETE /admin/agents/:id`, `/admin/keys/:id`, `/admin/oauth-clients/:id` - a no-JS form can only GET/POST, so the target id rides a form field (`agent_id`/`key_id`/`client_id`), not the path.

**Shared write path: `src/core.ts`.** HTTP (`POST /d`, `PUT /d/:id` in `src/index.ts`) and MCP (`src/mcp.ts`) share the publish/update/edit/read/read-text/revoke/list/find-by-slug/search cores (Where-things-live). Sanitization runs exactly once, inside core - new write surfaces route through core, never duplicating the sanitize -> cap-check -> R2 -> D1 sequence. `editDocumentCore` (MCP `edit_document` only, no HTTP `PATCH`) loads retained source S via `readDocumentSourceCore`, applies the edits (pure `src/edit.ts`), then DELEGATES to `updateDocumentCore` passing the doc's own `source_format` (no longer hardcoded `"html"` - wrong feeds Markdown to the HTML identity pipeline and corrupts *silently*). Match is against the STORED source (a Markdown doc edits its Markdown; reader theme survives); the response adds a `replacements` count. An OMITTED `expected_version` on `edit_document` is NOT a clobber (unlike `update_document`, where it is): it defaults to `current.version_no` - the version the source was read at - else an unguarded write silently reverts anything committed since the read while reporting `replacements: 1`; the agent gets a retryable `version_conflict`. `source_r2_key IS NULL` hard-fails `source_unavailable` - no fallback to H. `updateDocumentCore` collapses an IDENTICAL re-write to a no-op (contract `2.1.0`): when `sha256Hex(prep.sourceBytes)` equals the current version's `source_sha256` AND `sanitizer_v` + `source_format` match AND resolved title/description/tags/slug equal stored, it returns `unchanged: true`, `version = current_ver`, writing NOTHING - no version row, R2 blobs, FTS/link rows, vector re-embed, or `updated_at` touch. `prior_source_*` ride the `current_ver` join (zero extra round trips). Exists because `PUT` wasn't idempotent: a retry forked the version chain; one agent re-pushed an identical body every 30 min for ~1000 versions. Four rules: (1) keyed on source S, never H (a missed collapse is harmless; a false one swallows an edit); (2) `sanitizer_v` is part of the key - `sanitizer_version()` becomes a correctness dependency: a byte-affecting allowlist or `markdown_to_html` ingress change without a bump suppresses a needed re-render; (3) it sits AFTER the `version_conflict` check and slug lock - a stale base still conflicts, a public-doc rename still `slug_locked`s; (4) it compares against `current_ver` only, never `published_ver` - else it swallows the newest bytes on a doc awaiting promote. ALL-OR-NOTHING (a metadata-only change writes a full version) so `unchanged` can't lie. Pre-0015 rows (`source_sha256 IS NULL`) can't fire it - self-arms after one write. `publishDocumentCore` is never collapsed (`unchanged: false`). Covered by `test/e2e/no-op-collapse.sh` (no D1 harness in the unit suite). Listing-row reads (list/find-by-slug/search) share `LISTING_SELECT_COLUMNS`/`LISTING_JOINS` - add a `DocumentListing` column by updating those two constants once; all three follow. Wire-shaping centralized in `src/wire.ts` (Phase 2b): core returns `{ ok: true, … }` Results; the wire strips `ok` (revoke renames it `revoked`); `toWriteResponse`/`toEditResponse`/`toRevokeResponse` are the ONE copy (typed against `WriteResponse`/`EditResponse`/`RevokeResponse` in `contract.ts`), used by HTTP and MCP - don't re-hand-list fields; call the mapper.

**Text-read path runs at READ time, not write.** `readDocumentTextCore` pipes the sanitized HTML through `htmlToMarkdown` (same WASM module as `sanitize`, separate export); no per-version markdown cache in v1. Derived from sanitized H, so the text channel can't surface anything the sanitizer stripped. The `.src` blob is a separate read surface: `readDocumentSourceCore` fetches unsanitized S and re-runs the advisory pass (markdown-or-identity -> sanitize -> `detectAdvisories`), so a source-read carries `unsanitized: true` + `stripped[]`/`will_not_render[]` - divergence surfaced, never silent. Source-read is credential-gated - operator OR agent (operator >= agent), never anonymous (`requireReader`, `serve.ts`, refusing only anonymous): any agent key already reads/overwrites every doc, so source discloses no extra authority - and the operator must never rank below an agent (an earlier build gated `/source`+`/text` on `authenticateAgent` alone, locking the operator out). Render stays H-only, never serves S. Exception: `documents_fts` is populated at WRITE time via the same `htmlToMarkdown` - sole storage of body-as-text, only to feed BM25; reads re-derive fresh from R2. Drift ≤ one converter-version step - acceptable; the `converter_v` stamp signals it.

**Two security layers (in order):**
1. **Sandbox + strict CSP at render** (`src/serve.ts`): `GET /d/:id` returns a tiny shell with `<iframe sandbox>` (empty = all restrictions on); `GET /d/:id/raw` is what the iframe loads under `default-src 'none'` + `frame-ancestors 'self'`. Two URLs is deliberate - `frame-ancestors` is header-only, so the bytes must come from an HTTP response, not `srcdoc`. The load-bearing wall.
2. **Ammonia-WASM sanitization at write** (`sanitizer/src/lib.rs` -> `src/sanitizer.ts`): strips `<script>`, `<meta http-equiv>`, `<iframe>`, dangerous URL schemes, inline event handlers. Cheap insurance behind the CSP wall (covers `<meta refresh>`, which CSP can't). `<style>` blocks ALLOWED through (since v1.4; current stamp `ammonia-v1.7`): the sanitizer does NOT parse CSS (verbatim passthrough, as with inline `style="…"`) - CSS defense is Wall 1, not the allowlist (docs/design/style-support-design.md). `sanitize()` also runs one narrow post-pass over `clean()`'s output - the `target="_blank"` splice (new-tab convention); everything else is ammonia's parse-and-reserialize.

the migration's UPDATE backfills and every INSERT binds it - a surviving 1970 stamp = a write path forgot to bind. Nullable, no default/CHECK/FK/index: NULL = a real permanent "never published" state - presence-flag like 0008/0015, NOT 0017's sentinel (existence checks live in code, e.g. `version_not_found`); backfilled live public docs to `current_ver`. Invariant: `visibility='public'` => `published_ver IS NOT NULL`, held at four edges - `publishDocumentCore` binds at public birth, `setDocumentVisibilityCore` runs `published_ver = coalesce(published_ver, current_ver)` in the *same statement* as the flip, `revokeDocumentCore` nulls it, the migration covers history. A POINTER, not a fourth state axis - a private doc may carry one (staged); flipping back to private leaves it. Status is the third state axis (revoked = existence, visibility = anonymous read, status = currency); tags are classification like slug - behavior in the lifecycle and slug/tags convention bullets. R2 (`DOCS`): two blobs per version - sanitized render H at `<docId>/v<n>-<nonce>`, retained source S at the `.src` sibling (content-type from `source_format`). Keys are per-write-ATTEMPT, not per-`(docId, versionNo)` - nonce = 16 CSPRNG bytes (`newPublicId()`): two concurrent updates both compute `nextVer = current_ver + 1` (plain SELECT); one batch wins the `(document_id, version_no)` PK, and the loser's rollback used to delete the *winner's* bytes, bricking a live doc; per-attempt addresses mean it deletes only its own. Never re-derive an R2 key from `(docId, versionNo)` - every reader (`serveRaw`, text/source reads, link backfill, revoke purge) reads `versions.r2_key`/`source_r2_key`, opaque by design. Source bytes count toward the cap (`size_bytes` = rendered H, `source_size_bytes` = S; `checkStorageCap` SUMs both, NULL→0). `versions` rows are append-only, surviving revoke as audit trail (only R2 bytes purged: H and `.src`). KV (`OAUTH_KV`) belongs to the OAuth provider library (clients, grants, tokens). Vectorize (`VECTORIZE`) + Workers AI (`AI`) back semantic search (vector-search-design.md, BUILT): `slopcafe-docs` index (the shipped default; bound by `VECTORIZE`, so the name is per-deployment), 1024-dim cosine, N chunk vectors per doc keyed `${documents.id}#${i}`, model `@cf/qwen/qwen3-embedding-0.6b`. No D1 migration - the chunk ID yields the doc id; no per-vector metadata/chunk-count column (the fixed `#0…#${MAX_CHUNKS-1}` range-delete handles shrinkage); sole metadata field `preview` = non-indexed snippet. Sync is best-effort, eventually-consistent, OUTSIDE the D1 batch (vector-sync convention). On revoke, `documents.revoked_at` flips before the R2 delete (unreachable instantly even if R2 hangs); the same batch clears + tombstones the slug, deletes the FTS row, drops outbound `document_links`, stamps `updated_at` - kill + slug-retire + search visibility land atomically; the chunk-vector delete rides `ctx.waitUntil` (index reclaim, not the kill switch - the read-path re-join enforces `revoked_at is null` regardless). Revoke is IDEMPOTENT on the purge path: the R2 delete runs post-batch, chunked under R2's 1000-key limit (2 keys/version - a long-edited doc exceeds it alone), failures throw - re-issuing the revoke IS the recovery. A second `DELETE` on a revoked doc returns `200` and RE-RUNS the purge, skipping the D1 batch (no re-stamped `revoked_at`/`updated_at`); only unknown/malformed `public_id` 404s. Don't "fix" that back to a 404 - it claims a retry is pointless while unsanitized `.src` bytes stay resident forever.

**Single-tenant trust model.** Any active agent key can `PUT` to any document - `core.ts` deliberately does not scope updates by `created_by`. Write cores take an `Author` (`{kind:"operator"} | {kind:"agent";agentId}` - the `Principal` union from `access.ts` minus anonymous), NOT a bare `agentId: string` (migration 0013): the operator is a first-class author, never a fake agent (the old `restoreVersionCore("operator")` hack is gone). `documents.created_by`/`created_by_kind` keep the creator (`created_by` NULL for operator-created docs); per-version writer columns per 0013. The operator authors via `POST /admin/documents` / `PUT /admin/documents/:id` (`admin.ts`), same core path. `listDocumentsCore` shows the whole fleet to every caller; if per-agent scoping is ever needed, add a `createdBy?` core arg. Agents can also CURATE - `PUT /d/:id/tags` + `PUT /d/:id/status` (`curateDocumentTags`/`curateDocumentStatus` in `admin.ts`, `requireReader`-gated) and the MCP `set_document_tags`/`set_document_status` tools (same cores). Not a widening: an agent key already replaces any document's entire content, so re-tagging/deprecating grants strictly less. `visibility`, revoke and PROMOTION stay `requireOperator`, deliberately - visibility is the boundary between fleet-private and anonymous-readable, revoke is irreversible, and promotion (`POST /admin/documents/:id/promote`, migration 0018) moves bytes ACROSS that boundary - an agent that could promote its own write would re-create the exfiltration path `published_ver` closes. There is no agent-reachable promote and none may be added - not an HTTP twin on `/d/`, not an MCP tool, not a `published_ver` input on a write tool - same reason no MCP tool takes `visibility` as input. Agents SEE the pointer (every MCP write/read envelope echoes `published_version`) to report "stored but not live yet"; they never move it. A new classification surface goes agent-side only after asking which side of THAT line it falls on: tags/status qualify because neither reaches an anonymous surface; promotion is defined by reaching one. Unsanitized source bytes are at rest in R2 (the `.src` blob, since 0008): credential-gated (operator or agent, never anonymous), never served to a browser - render stays H-only behind the iframe+CSP wall; `representation:"source"` changes only the ingestion-as-context surface (it can pull markup the sanitizer would neutralize on render), provenance tag + credential auth cover exactly that increment, and revoke purges `.src` alongside H so the kill switch leaves no unsanitized source resident.

**Per-document visibility - a two-axis read model (migration 0011, issue #7).** Orthogonal to revoke: every document is `public` or `private`; `src/access.ts` is the single pure chokepoint. `canRead(principal, doc)` is top-down first-match-wins (revoked→false, operator→true, agent→true, anonymous→`visibility === "public"`); `resolvePrincipal` resolves operator -> agent -> anonymous. Visibility gates ONLY the anonymous browser surface - `serveShell`/`serveRaw`/`serveBySlug`/`serveHomepage`, enforced at the `serveRaw` chokepoint (`resolvePrincipal` -> `canRead`). The operator (cookie OR bearer) and any agent key read everything - `/text`, `/source` (`requireReader`, operator >= agent), MCP read/list/search, `listDocumentsCore` all unaffected. A private doc denies as the same opaque 404 as missing/revoked - never a 401, no existence oracle. New docs are born at `DEFAULT_DOCUMENT_VISIBILITY` ([var], default `"private"`), bound EXPLICITLY by the write path (the column's `DEFAULT 'public'` covers only legacy rows); the operator flips it via `POST /admin/documents/:id/visibility` or the Manage page (`setDocumentVisibilityCore`, no version bump). Visibility-CHANGE authority is a separate operator check (`requireOperator`), deliberately OUT of `canRead`. Because an agent can neither set nor undo it, every MCP write/read envelope echoes `visibility` so an agent knows before handing a human a URL that 404s for them (`mcpVisibilityEcho` in `contract.ts`; `currentEcho` in `mcp.ts` re-reads the row, also carrying the 0018 `published_version`). No MCP tool takes `visibility` as an INPUT and none should be added - the identical rule covers `published_ver` (trust model).

**Sanitizer is bundled as WASM.** `src/sanitizer.ts` imports `sanitizer/pkg/sanitizer_bg.wasm` directly as a `WebAssembly.Module` (wrangler `[[rules]] type = "CompiledWasm"`) and calls `initSync`. Do not use the wasm-pack `--target web` glue's `init()` - it fetches via `import.meta.url`, which doesn't exist on Workers. Init is lazy and idempotent. (The `[[rules]] type = "Text"` rule covers `**/*.html` AND `**/*.md`, bundling `src/mcp-app-template.html` as the `ui://` viewer template and the generated `src/generated/docs/*` corpus. **#38's rationale is intact and is about MCP RESOURCES, not bundling**: the publishing guide is still not a resource, because resources aren't surfaced to most connector models — it reaches an agent as a seeded DOCUMENT (`slopcafe-docs-publishing-guide`) and a human as a route (`/docs/publishing-guide`). Don't read "it's bundled again" as licence to re-register it as a resource.)

**MCP server lifecycle.** `src/mcp.ts` builds a fresh `McpServer` per request (SDK v2, `@modelcontextprotocol/server`, 2026-07-28 line; the old `@modelcontextprotocol/sdk` remains only as `agents`' exact v1 peer - never import it), a factory for stateless `createMcpHandler` (`agents/mcp/server`), per MCP 2026-07-28 (`server/discover` + auto legacy `initialize` fallback: ONE factory, both eras). Per-request survives the upgrade (was "SDK >=1.26 throws on reuse"; v2 formalizes it - single-connect instances, cross-request state leaks). agents 0.20 validates Origin/Host: server-side connectors send no Origin and pass; `allowedOriginHostnames` exists for a future browser-origin client - documented, deliberately unconfigured. **SEP-2549 cache hints (issue #45):** constructor `cacheHints` on `tools/list` + `server/discover` (`STATIC_SURFACE_CACHE_HINT`: 1 h `public` - static per deploy, identical per principal; rationale on the constant); 2026-era only (2025 codec: no cache path); since MCP Apps, `resources/list` (third entry) + the ui:// template's `resources/read` (per-registration `cacheHint`) share it; `prompts/list` N/A. The eleven tools (named in the `src/mcp.ts` bullet) close over upstream-resolved `props.agentId` - never re-validate auth; `create_publish_credential` (lone non-document tool) mints a short-lived `awh_` key for the byte-exact curl path via `mintEphemeralKey` (convention bullet). `view_document` = the MCP Apps presentation read (SEP-1865, extension `io.modelcontextprotocol/ui`) - SHOW to the human vs `read_document`'s ingest. `public_id` XOR `slug` (+ optional `version`); ONE flat envelope (resolved id, `/d/<id>` url, metadata echoes incl. `visibility`/`published_version`, FULL sanitized H as `content`, `format:"html"`) riding `structuredContent` ONLY - model-facing text = body-less metadata summary + note; a retired-but-redirecting slug errors `slug_retired` naming the target, never a second envelope shape. `DOC_VIEW_TOOL_META` links it in BOTH spellings (nested `ui.resourceUri` + deprecated flat `"ui/resourceUri"`; each host generation reads only its own) to the `ui://slopcafe/document-view.html` template (`src/mcp-app-template.html`, mime `text/html;profile=mcp-app`) and rides the three content-write tools (post-publish inline preview: a write envelope has no body - the template fetches via a version-pinned proxied `tools/call view_document`, degrading to a metadata card); exactly four tools carry it, pinned by `test/mcp-errors.test.mjs`. Apps hosts (Claude web/desktop, ChatGPT) fetch it via ordinary `resources/read` and render it in THEIR sandboxed iframe under THEIR deny-all CSP; capabilities advertise `resources: {}` + `extensions: {"io.modelcontextprotocol/ui": {}}`. Registration is UNCONDITIONAL per request (hosts may prefetch); non-Apps hosts ignore `_meta` + ui:// and render the structured JSON - graceful degradation (Claude Code is not an Apps host; Claude mobile unconfirmed; mcp-apps-design.md). `set_document_tags`/`set_document_status`, the two CLASSIFICATION writes: full-replace tags (`[]` clears; tags silently *sanitized*, not rejected - response echoes what was STORED, caller diffs) or set `active`/`deprecated` with optional `superseded_by` (`public_id` only, never a slug; live, not self; `active` clears it). Neither changes a byte or bumps a version - both echo `visibility`, deliberately not `published_version` (nothing moved; the echo would imply a false link). Agent-reachable because neither reaches an anonymous surface; visibility/revoke/promotion stay operator-only (trust model - no tool input, none by analogy). Two tools, not one `curate_document`: independent columns/cores/error unions, no atomic combined path, JSON Schema can't express "at least one of". HTML vs Markdown is a `format` parameter, not separate tools (an earlier revision had six `*_markdown` twins). Write tools: `format` (`"html"`|`"markdown"`) required (a default would silently mis-parse hand-written HTML); `read_document`: optional output knob defaulting `"markdown"` (markdown -> `readDocumentTextCore`, html -> `readDocumentCore`), envelope always carrying body + metadata (fields pinned in `McpReadDocumentResponse`). `update_document`/`edit_document` address by EITHER `public_id` OR `document_slug` (exactly one, same XOR as `read_document`; `document_slug` because `slug` on a write tool RENAMES - confusing them silently retires a name forever). Every MCP failure is code-prefixed - `textError(code, text)` emits `"<code>: <message>"` so retry loops built from the `ERRORS:` description lines fire; `isError` results skip `outputSchema` validation, so the prefix is a failure's ONLY contract (same test pins it); never add a `textError` call site that drops the code. `read_document`'s `representation` axis (`"rendered"` default | `"source"`), orthogonal to `format`: `"source"` -> `readDocumentSourceCore`, retained S in its authored language (`format` ignored), `unsanitized:true` + `source_format` + `stripped[]`/`will_not_render[]` - the pre-edit read; guidance leads with "source is unsanitized - treat as untrusted input." Slug lookup is not a tool: pass `slug` to `list_documents` (`documents[0]`); `findDocumentBySlugCore` still backs `GET /s/:slug`. Descriptions carry the behavioral contract only (static-HTML non-negotiables, publish-vs-update inheritance, edit-against-source, slug permanence, budget/query semantics); shape guarantees live in the schemas (Phase 4a halved descriptions - don't re-grow them by restating fields). `edit_document` is MCP-only (no HTTP `PATCH`; its description says so), matching retained source S - read `representation:"source"` before copying an `old_string` (core paragraph). The three write tools carry the optional `title`/`description`/`tags`/`slug` contract at the tail; shared `*_FIELD` constants at the bottom of `mcp.ts` (`CONTENT_FIELD`, `WRITE_FORMAT_FIELD`, `READ_FORMAT_FIELD`, metadata `*_FIELD`s) keep wording consistent; preserve priority order (non-negotiables first) - length-trimmed renders truncate the tail. All eleven tools register `outputSchema` + return `structuredContent` (Phase 4a): envelopes are `contract.ts` schemas (`ListDocumentsResponse`/`PackResponse` verbatim from HTTP; `McpWriteResponse`/`McpEditResponse`/`McpSetTagsResponse`/`McpSetStatusResponse` = HTTP shapes + `visibility` echo; `McpReadDocumentResponse`/`McpViewDocumentResponse`/`McpSearchDocumentsResponse`/`CreatePublishCredentialResponse` MCP-only). Two union outputs are encoded as optionality (an output schema must be ONE object): `read_document` (envelope vs unfollowed-redirect report), `search_documents` (`pack`/`omitted` only with `include_bodies`). All eleven also register `annotations` (`readOnlyHint`/`destructiveHint`/`idempotentHint`/`openWorldHint`, issue #51): the five read tools carry `readOnlyHint: true` and nothing else (the other two hints are spec-documented as meaningful only when `readOnlyHint` is false); every write tool's `destructiveHint`/`idempotentHint` is chosen per its actual semantics (`update_document` genuinely idempotent since the 2.1.0 no-op collapse, `edit_document` not - a repeat apply fails or double-replaces); `openWorldHint` is `false` everywhere (closed corpus, this origin only); `test/mcp-errors.test.mjs` pins the exact `readOnlyHint` set so a new tool can't land un-tiered.

## Conventions and gotchas

- **`If-Match` is required on `PUT /d/:id`** (428 if missing). Send `"v<n>"` for optimistic concurrency or `*` to skip. Strong tags only; no weak tags, no multi-tag lists.
- **`POST /d` / `PUT /d/:id` accept `Content-Type: text/html` or `text/markdown`** (`text/x-markdown` too; else 415; gate `parseInputFormat`, `src/index.ts`). Markdown parses (CommonMark+GFM) to HTML pre-sanitize; stored bytes are always sanitized `text/html; charset=utf-8`; input path recorded in `versions.source_format`.
- **Optional `X-Content-SHA256` byte-exact integrity check on `POST /d` / `PUT /d/:id`** (`src/integrity.ts` via `readVerifiedBody`). Hashes the **raw body before sanitization**—verifies the wire, not the sanitizer; orthogonal to `modified`. Malformed header→400 `bad_integrity_header`; mismatch→422 `integrity_mismatch`. **HTTP-only by design** (companion to the `curl --data-binary @file` path): the hash must come from the deterministic tool streaming the file—no MCP equivalent. Rationale: `byte-exact-publish-design.md` (the 66–85 KB constraint is model regeneration of `content`, not transport).
- **Short-lived publish credentials (`agent_keys.expires_at`, 0007).** The byte-exact curl path needs a shell bearer connectors can't hold—so the MCP session mints it: `create_publish_credential`→`mintEphemeralKey` (`src/admin.ts`), a normal `awh_` key with non-NULL `expires_at` (default 15 min, max 60, clamped). `authenticateAgent` rejects expired like revoked (pure `isKeyExpired`); `expires_at = NULL` = never (operator-minted + legacy). **No scope column in v1**—single-tenant; the key grants nothing beyond the session's authority. The minted **`key`** is the deliberate disclosure surface—never log it. **The `recipe` is NOT a secret** (issue #34): it references the key via `$AWH_KEY` (`export` once; space-prefix to skip shell history)—the token never reaches the curl command line. Don't "re-harden" by interpolating `result.key` back in (the leak #34 removed). Revoke early: `DELETE /admin/keys/:id`.
- **Optional metadata on POST/PUT /d**: `X-Doc-Title`, `X-Doc-Description`, `X-Doc-Tags` (comma-separated), `X-Doc-Slug`; MCP write tools take the same fields. **Header values are read as UTF-8** (`decodeHeaderUtf8`, issue #31)—headers arrive as Latin-1 byte views (Fetch ByteString); undecoded non-ASCII = mojibake. Fatal-with-fallback: ASCII identity, valid UTF-8 recovered, a lone Latin-1 byte preserved as-is. Agents send non-ASCII literally, not entity-encoded (the sanitizer normalizes entities to UTF-8; only `& < > "` + `&nbsp;` stay encoded). On UPDATE an *omitted* field inherits (slug: the document's current); explicit `""` clears (title re-derives from H1; slug releases). Tags charset `[A-Za-z0-9_-]`—invalid chars silently stripped. Slug charset `/^[a-z0-9](?:[a-z0-9_-]{0,62}[a-z0-9])?$/`—invalid input **rejected** (`invalid_slug` 422), never sanitized (mutating a unique key could surprise-collide). Slug unique across live docs (partial UNIQUE INDEX); conflict→`slug_taken` 409. Bidi/zero-width strip on title only; description keeps bidi (never reaches the browser tab).
- **Slug AND tags live on `documents`, not `versions`.** Document-level (tags since 0012)—slug identity-adjacent, tags classification; both survive updates/restores, changes never bump a version; slug changes are atomic claim-new + retire-old in one D1 batch. On revoke (and rename/clear) `documents.slug` goes NULL but is **NOT reusable**—retired into `slug_tombstones` (0009) forever; `/s/<slug>`→**410 Gone**, reclaim→`slug_retired` (reverses release-on-revoke, issue #6—shared links must not silently change content). `documents.slug` = the live slug; claims check both via `resolveSlug`; a live-lookup miss consults `findSlugTombstoneCore` (410-vs-404). Read/list queries pull slug from `d.slug`, not prior_metadata. **A retired slug can REDIRECT (0010, `slug_tombstones.redirect_to` = target `public_id`), but only LOUDLY:** rename auto-forwards to the same doc's `public_id`; operator cross-redirects via `POST /admin/slugs/:slug/redirect`; never auto-followed—browser: click-through interstitial; agent: `409 slug_redirected` (HTTP) / `{redirected:true}` (MCP), opt-in via `follow_redirects`. Single-hop (`public_id` target—no chains/loops; dead target→410). **The target is additionally `canRead`-gated** (`redirectTargetReadableBy`): to an anonymous caller an unreadable target = a dangling one—plain 410, never named (no private-doc oracle). `resolveRedirectTarget` filters `revoked_at is null` but deliberately NOT `visibility`—**every caller must gate the result itself**. Escape hatches: `DELETE /admin/slugs/:slug` force-releases a tombstone (the only un-retire path); `…/redirect` drops just the redirect. **An AGENT may not change the slug of a PUBLIC document—`slug_locked` (403), 0018/issue #43:** renaming a ~60-char operator-chosen name at an anonymous-readable address was a write channel onto the open web that `published_ver` can't cover (renames are immediate, no promote). Enforced once in `updateDocumentCore`, keyed on the resolved slug *action*, not field presence: re-sending the existing slug is a clean no-op; rename **and clear** both lock (`invalid_slug`/`slug_taken`/`slug_retired` can fire first). Via delegation (`editDocumentCore`/`restoreVersionCore`) one check covers `PUT /d/:id`, MCP `update_document`/`edit_document`, restore-with-slug; publish (brand-new doc) and operator slug changes are exempt. Content writes unaffected—the lock is the slug field alone; remedy: re-send without a slug field or ask the operator. **`tags`/`status` were checked against this line and deliberately NOT restricted**—neither reaches an anonymous surface (see the trust-model paragraph). **The `slopcafe-docs-` prefix is RESERVED** (`RESERVED_SLUG_PREFIX`/`isReservedSlug`, `metadata.ts`; issue #4): every writer—agent AND operator—is refused with `invalid_slug` + `reason:"reserved_prefix"`, enforced once in `resolveSlug` behind an explicit `allowReservedSlug` flag that ONLY the seeder passes. Operators are included on purpose: a hand-authored doc at one of these names would be indistinguishable to an agent following a tool description, and would collide the moment the seeder ran.
- **Operator document-management page + browser login-link 404 (`src/serve.ts`).** `GET /d/:id/manage` (`serveManagePage`), cookie-session-gated, folds visibility (`POST /d/:id/visibility`)/slug/tags/status/revoke (their `handle*Form`s) plus read-only Version history and Link graph panels. Logged-out→sign-in card, **no DB hit** (no existence oracle). **`GET /d/:id/revoke` (`serveRevokeConfirm`) resolves operator auth BEFORE any DB read** (previously an existence-branching oracle for private docs); an `Authorization`-carrying caller gets opaque `notFound()`; a plain browser gets the paste-the-token confirm card with **no query**—bytes identical for any id (a wrong id fails at POST). Shell topbar kebab = **"Manage…"**. JSON twins in `admin.ts`: `setDocumentVisibility`/`setDocumentSlug` (no version bump; rename auto-forwards). **Browser login-link 404:** a valid `/d/:id` or `/s/:slug` 404s to a logged-out operator, so `notFoundBrowser` (+ `NOTFOUND_CSP`) returns an HTML 404 card with a Sign-in link via `/login?next=<requested URL>`; it **never reads doc state** (only echoes the path)—a private doc's 404 is byte-identical to a nonexistent one's. Wired into `serveShell` (all three 404s), `serveBySlug` (HTML-vs-plain picked by the `Authorization` header), `serveRetiredSlug`'s no-tombstone case. Byte/HTML surfaces (`/raw`, `/v/:n/raw`, shells, `/manage`+`/revoke` POSTs) keep plain `notFound()`; `/text`/`/source`/`/links` answer `notFoundJson()` (JSON-404 bullet).
- **Operator version history + restore-as-new-version.** No migration—`versions` already retains every version's bytes (H + `.src`) until revoke purges. Surfaces: `GET /d/:id/v/:n` (+ `/v/:n/raw`), `authenticateOperatorRequest`-gated (Bearer OR cookie); manage-page history table with per-row Restore (`POST /d/:id/restore`). **JSON twins**: `GET /admin/documents/:id/versions` (→ `ListVersionsResponse`) and `POST /admin/documents/:id/restore` `{version:n}` (→ write envelope + `restored_from`), both `requireOperator`, over `listVersionsCore`/`restoreVersionCore`. Check `source_present` per row before offering Restore. An **operator** axis, NOT folded into `canRead`/visibility—a public doc's history is as operator-only as a private one's; non-operator→opaque 404. Agents read history via MCP `read_document` (`version`, `include_history`)—**read-only; no agent restore in v1.** **Restore is mandatorily restore-as-NEW-version, never a `current_ver` rewind:** `updateDocumentCore` computes `nextVer = current_ver + 1`; a rewind makes the next update collide on the `(document_id, version_no)` PK. `restoreVersionCore` re-publishes version N's retained source S forward through `updateDocumentCore`—restores body + title/description/tags, keeps the current slug (identity, not content). A pre-0008 version with no source **hard-fails `source_unavailable`**—NO fall-back-to-H (same as `edit_document`); the manage table shows muted "no source"; such docs are revoke-and-republished. No D1 harness in the unit suite—covered by typecheck + the `wrangler dev` E2E.
- **The served-version rule is a security boundary; `src/served-version.ts` is its ONE copy (0018, issue #43).** `served = (visibility === 'public' && published_ver !== null) ? published_ver : current_ver`. It contains **no principal term**, deliberately: a public doc serves its promoted version to anonymous, agent and operator alike—showing the operator newer bytes would blind the one person who can promote to what readers see (staged work has its own address, `/d/:id/v/:n`). Private renders current: private is *already* the gate; staging would only add an operator round-trip. **HTML byte path ONLY**—`GET /d/:id`, `/d/:id/raw`, `/s/:slug`, `/` (ETag keys on the SERVED version; shell metadata + interstitial title follow it). **Everything credentialed or machine-readable stays on `current_ver`—not an oversight to "align"**: `/text`, `/source`, `/links`, every MCP read/list/search, packs, FTS, vectors, the link graph, the operator's `/v/:n` reads—those callers already read the whole corpus; a stale render protects nothing and makes `edit_document` patch bytes it can't see; the gate is about what LEAVES the fleet. `served-version.ts` is a **leaf module** (no runtime imports; `Visibility` is `import type`): both `serve.ts` and `core.ts` need it and the reverse edge is a cycle—a drifted second copy of *this* rule is a silent anonymous-disclosure hole. Two exports: `SERVED_VER_SQL` (SQL fragment—**alias the documents table as `d`**; interpolated not bound: names columns, no caller input) and `servedVersion(doc)`. **Adding a render site = routing through one of those two**—a site left on `current_ver` re-opens exactly the path 0018 closed. Gate `revoked_at is null` first (revoke nulls both pointers; stale pointers join against purged R2 keys). Related: `/d/:id/raw` emits **`x-doc-current-version`** for non-anonymous principals only—absent for anonymous, so staged work's existence is never disclosed—because `/raw`'s ETag names the SERVED version and is no longer a valid `--if-match` preflight; writers prefer the header, ETag only when absent.
- **The machine-readable read routes answer JSON, not `text/plain`—their 404 may carry a shape hint.** `/d/:id/text`, `/d/:id/source`, `/d/:id/links` return `notFoundJson()` (`{error:"not_found", message}`)—their 401s/409s were already JSON, so plain text made the commonest failure the unparseable one. **Opacity unchanged**: missing/revoked/private/malformed-id answer identically for the same URL. Only `message` varies, via the exported **`idShapeHint(id, slugRoute)`**—purely syntactic, from the caller's own path segment, **no DB read**, never an existence oracle. A segment failing `PUBLIC_ID_RE` but valid as a slug names the conversion (`GET /d?slug=…`, plus `/s/:slug/text` where a slug twin exists—`/source`/`/links` have none). A well-formed `public_id` gets the bare message: the `PUBLIC_ID_RE` guard is load-bearing—a lowercase id also satisfies the slug charset; "that isn't a public_id" would be wrong. Reused by `PUT /d/:id` and every `/admin/documents/:id/*` mutator (`documentNotFound`). NO auto-resolve of a slug in the id slot—blurring the two is how a shared `/s/<slug>` gets treated as an unguessable capability URL.
- **`version_not_found` is a first-class `ErrorCode`, emitted only ever behind an operator gate.** The two doc+version routes—`POST /admin/documents/:id/restore` and `/promote`—used to report a version miss as `404 not_found` with an optional `version` field: the discriminator between two misses with **different remedies** (give up vs. pick another version) was a field's *presence*, invisible to a client switching on `error`. The split (2.0 ledger entry 7) gives the miss its own code with `version` REQUIRED; `not_found` is context-free again. **Status unchanged (404)—the break is the discriminant.** **Hard rule: never emit this code on an anonymous-reachable surface.** Safe on those two routes *only* because `requireOperator` already ran (the operator can enumerate `GET /admin/documents/:id/versions`—nothing disclosed); MCP `read_document`'s `version` arg has surfaced the identical token via `textError` all along. Anywhere anonymous, "live doc but no such version" separates a real doc from a missing one—the existence oracle every opaque 404 in `serve.ts` prevents. The same change *declared* `source_unavailable`'s optional `version` context (previously undeclared—a latent spec violation: `ErrorBody` members are `additionalProperties: false` in `openapi.json`).
- **`GET /d/:id/text` and `/s/:slug/text` content-negotiate on `Accept`.** `application/json`→the `ReadTextResponse` envelope (body **plus** title/description/tags/slug/status/superseded_by); anything else (wildcard/no header) keeps the historical `text/markdown` body. `Vary: Accept` on both. Why: a metadata-less body pushed callers toward the `/source` shortcut—ingesting UNSANITIZED bytes as context. Negotiation, not a `/text.json` route: those URLs already negotiate (on `Authorization`); the shape existed in `contract.ts`.
- **Every JSON error carries `Link: </openapi.json>; rel="service-desc"`; `/healthz` is the in-band API map**. The JSON-error helpers (`jsonError` in `index.ts`, `jsonError`/`documentNotFound` in `admin.ts`, `operatorError` in `session.ts`, `unauthorizedJson`/`notFoundJson` in `serve.ts`) attach the RFC 8631 relation; credentialed 401s + the catch-all 404 append `API_DISCOVERY_HINT`; `/healthz` carries absolute `openapi`/`docs`/`mcp` pointers built from the **request** origin. `SERVICE_DESC_LINK` lives in `serve.ts` (imported by `index.ts`/`admin.ts`); `session.ts` keeps its own copy (reverse edge = module cycle). A fourth copy→promote to a leaf module.
- **Agent-reachable classification writes are `PUT`, not `POST`.** `PUT /d/:id/tags` + `PUT /d/:id/status` (`curateDocumentTags`/`curateDocumentStatus`, `requireReader`) twin the operator's `POST /admin/documents/:id/{tags,status}`—`PUT` because `POST` there is taken by the manage page's HTML forms, and both are full replacements of a subresource, not appends. Same bodies/cores/responses; only the door differs. MCP `set_document_tags`/`set_document_status` are the third door onto the same cores (`public_id` XOR `document_slug`, + `visibility` echo). Three doors, two cores; why not `visibility`: the trust-model paragraph.
- **`public_id` regex is fixed**: `/^[A-Za-z0-9_-]{22}$/` (`PUBLIC_ID_RE` in `src/serve.ts`). Safe to interpolate into HTML templates after this check; `serveShell` does so.
- **Storage cap is best-effort, but FAILS CLOSED on a bad `[var]`.** `checkStorageCap` runs `SUM(size_bytes)` outside the insert batch; two concurrent writes can both pass—v1 accepts the overrun. **`storageCapBytes(env)` in `core.ts` is the SINGLE reader of `STORAGE_CAP_BYTES`** (cap check, console dashboard, `/healthz` can't disagree). The `[var]` is typed `string`—shape only: the old inline `Number(env.STORAGE_CAP_BYTES)` turned `"2 GiB"` into `NaN`, every `NaN` comparison is false—guardrail silently DISABLED, no log. Now non-finite/≤0 logs and falls back to `DEFAULT_STORAGE_CAP_BYTES` (2 GiB, as `wrangler.toml.example`). Never re-introduce a raw `Number(env.…)` read.

Naming a resource at CREATION time is the opposite case and stays literal: `wrangler d1 create slopcafe-meta` in the setup guides, `database_name`/`bucket_name`/`index_name` in `wrangler.toml.example`. **Caveat:** within one config wrangler matches `database_name` BEFORE `binding`, and `d1 execute`—unlike `migrations apply`/`list`—has no config-miss guard, so a second `[[d1_databases]]` entry literally named `META`, or an invocation with no `wrangler.toml` in scope, can resolve somewhere unintended.
- **Wrangler version + Workers types.** `compatibility_date = "2026-05-26"` with `nodejs_compat` (also covers the agents MCP handler's `AsyncLocalStorage` plumbing). Types devDep is on `@cloudflare/workers-types@^5` matching `wrangler`'s peer.
- **The `overrides` block in `package.json` closes Dependabot alerts upstream won't; removing an entry silently re-opens a CVE.** Every npm alert here has been *transitive*; the entry is the one plain `npm install` can't reach: **`@hono/node-server: ^2.0.5`** (the `serve-static` path-traversal fix was a MAJOR bump the MCP SDK's `^1.19.9` pin couldn't reach; since SDK `1.30.0` the range is `^1.19.9 || ^2.0.5`, so the override is belt-and-suspenders against a transitive re-pin). Transitives with semver-reachable fixes (`hono`, `fast-uri`, `qs`, `body-parser`) were healed by targeted `npm update <name>`—**prefer that**; override only when the fix sits outside the parent's declared range. **Triage reachability before treating an alert as urgent**: `npx wrangler deploy --dry-run --outdir <dir>`, then read `index.js.map`'s `sources`—the Worker bundles only 8 npm packages (`@cfworker/json-schema`, `@cloudflare/workers-oauth-provider`, `@modelcontextprotocol/{core,core-internal,server}`, `agents`, `content-type`, `zod`); everything else in the alert list is dev-tree (miniflare) or the v1 SDK's never-imported Express transports. **`npm audit fix` does not work here**—it re-resolves the tree and dies on a pre-existing peer conflict in the `agents`→`@cloudflare/ai-chat`/`ai` chain; use targeted `npm update` + override, never `--force`/`--legacy-peer-deps`.
- **Secrets** (`HMAC_PEPPER`, `OPERATOR_TOKEN`) live in `.dev.vars` for local dev (gitignored) and `wrangler secret put` for production—never `[vars]` in `wrangler.toml`. `SESSION_EPOCH` is the exception: a non-secret rotation counter in `[vars]` (default `"1"`); bump it to invalidate all browser sessions. `CORS_ALLOWED_ORIGINS` is `[vars]` too (non-secret, empty/unset = CORS off — `src/cors.ts` bullet), as is `HOMEPAGE_PUBLIC_ID` (non-secret, empty/unset = placeholder at `/` — `src/serve.ts` bullet). Both are per-deployment state that must stay OUT of tracked source: `wrangler.toml` is gitignored precisely so this instance's values never ship to a fork.
- **Every code file carries an SPDX header** (Apache-2.0, issue #15): `// SPDX-FileCopyrightText: 2026 Skylled / Kyle Bradshaw` then `// SPDX-License-Identifier: Apache-2.0` on every `.ts`/`.rs`/`.mjs` file; **a new code file MUST get it.** Deliberately NOT headered: `.md` (`skills/publishing.md` + the bundled `docs/` corpus are served byte-exact—a header would corrupt served bytes), `.sql` migrations, config (`wrangler.toml`, `tsconfig.json`, `package.json`).
