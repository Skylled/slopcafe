# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> **Operator-instance specifics — forkers, read this.** This repo is the source for Kyle's `slopcafe.com` deployment. A few obligations below are tied to *that specific instance*, not to the code: the remaining hard-coded `public_id`/`slug` values point at documents in Kyle's corpus on `slopcafe.com`. If you fork this and run your own deployment, treat those as *examples* — nothing in the code depends on them. (The documentation corpus USED to be the biggest such coupling; issue #4 removed it — docs are bundled and served from `/docs/<name>` on every instance, with no per-instance ids anywhere in the registry.) Same for infrastructure names: the repo ships `slopcafe`/`slopcafe-docs`/`slopcafe-meta` defaults, but the live deployment still runs on its original `agent-web-host-*` resources — `wrangler.toml` is gitignored, so the two diverge harmlessly (naming bullet). Everything else here (the architecture, the conventions, and the source-↔-`docs/` sync rules that don't mention Slopcafe) is instance-independent.

## Commands

```sh
npm run dev            # wrangler dev — uses .dev.vars + local D1/R2
npm run typecheck      # tsc --noEmit
npm run build:wasm     # rebuild the Rust→WASM sanitizer (auto-run via predeploy)
npm run build:docs     # rebuild the bundled /docs corpus (auto-run via predeploy)
npm run deploy         # rebuilds WASM + openapi.json + the docs bundle, then `wrangler deploy`
```

Database (D1):
```sh
npm run db:migrate:local            # apply migrations to local D1
npm run db:migrate:remote           # apply migrations to remote D1
npm run db:console:local  "SELECT * FROM agents"
```

`predeploy` injects `$HOME/.cargo/bin` into PATH so `wasm-pack` resolves from a fresh shell. Rust toolchain (`rustup` + `wasm32-unknown-unknown` target + `wasm-pack`) is only required for `build:wasm`.

## Git workflow

When the operator says "commit your work" (or similar) without specifying a branch, **commit straight to `main`** — do not branch first. The operator deliberately delegates commits to the agent so the work shows up credited in the log; keep using the standard `Co-Authored-By` trailer. Still only commit/push when explicitly asked, and push only on explicit request.

## Architecture

**Single Worker, one origin.** `src/index.ts` exports `innerHandler` (exact-match route dispatch); the default export wraps it in `@cloudflare/workers-oauth-provider` (`src/oauth.ts`). The OAuth wrap intercepts `/mcp` (its `apiRoute`), validates the token and populates `ctx.props.agentId`; everything else (incl. `/authorize` and the `awh_`-bearer path on `/mcp`) goes to `defaultHandler`. The inner handler is registered as both — the only difference is whether `ctx.props.agentId` is populated. Routes match `method === "GET"` literally, so `withHeadSupport` normalizes `HEAD` to `GET` (original headers, so every gate is unchanged; body stripped): `HEAD /d/:id/raw` gets the `GET`'s `text/html`/`ETag`/CSP, and a private/missing doc still `HEAD`s as the same opaque `404` (issue #36). **Full stack, outermost first: `withAudit(wrapWithOAuth(withCors(withHeadSupport(innerHandler))))`.** `withAudit` (0020/#62) is OUTSIDE the provider because that is the only place `/register` + `/token` are visible (the provider answers them itself) and is OBSERVE-ONLY: it returns the inner response unchanged, reads only the status (+ `client_id` off a `clone()` on a 2xx `/register`), never a secret/body/header, and rides `ctx.waitUntil`; it also files `mcp_auth_failed` on a `/mcp` 401. `withCors` sits INSIDE the OAuth wrap deliberately: the provider CORS-stamps `/mcp`+`/token`+`/register`+its `/.well-known/*` itself, and wrapping outside would double-write `Access-Control-Allow-Origin` (browsers reject that); inside, it sees exactly the `defaultHandler` surface our allowlist governs (hence `/mcp` is NOT `isCorsEligible`). It sits OUTSIDE `withHeadSupport` so it stamps the synthesized `HEAD` responses too. **ONGOING OBLIGATION: every route added to `innerHandler` must be classified in `isCorsEligible`** — default-deny, so forgetting fails safe but silently; a new cookie/HTML surface under `/admin/` goes in the exclusion ahead of the `/admin/` catch-all in the same change.

**Two auth doors converge on one identity (`AwhProps` = `{agentId, clientId, via}` in `src/mcp-auth.ts`; `clientId` is the Door A grant's OAuth `client_id`, `null` on Door B — migration 0019/issue #63, attribution only, and the `/mcp` dispatch still gates on `agentId` alone):**
- **Door A (OAuth 2.1 + PKCE)** - one pre-registered client per agent: bound mint `POST /admin/agents/:id/oauth-clients`; unbound mint `POST /admin/oauth-clients` (KV record, no `oauth_clients` row; agent picked at consent). DCR (`POST /register`, RFC 7591, on when `ENABLE_DCR` in `src/oauth.ts`; public PKCE-only clients allowed for native CLIs like `claude mcp add`; 90-day TTL; dcr-design.md): a DCR client arrives unbound and rides bind-or-mint. Consent UI `src/authorize.ts`; operator approves via `OPERATOR_TOKEN` or browser session; `agentId` = the grant's `encryptedProps` via `ctx.props`; `props.clientId` is stamped at the same point from `authReq.clientId` (provider-parsed, NEVER a form field) and lands in `versions.author_client_id`. Every 302 to a client callback, allow and deny alike, carries RFC 9207 `iss=<request origin>` via the pure `appendIssParam` (overwrite-if-present; the provider does not emit it as of 0.8.2 — pinned in `test/authorize-callback.test.mjs`); in-place HTML errors never reach the callback. Three operator-gated inline repairs, none disclosing client state to non-operators: (1) **TOFU callback approval** — register an unregistered `redirect_uri` whose host is in `APPROVABLE_CALLBACK_HOSTS` (`src/admin-oauth.ts`: `claude.ai`/`claude.com`/`chatgpt.com`; `validateCallbackUri` in `session.ts` is the https-only gate). That allowlist is decoupled from the consent CSP `form-action`, which is the deliberately broad `CONSENT_FORM_ACTION_SOURCES` (`authorize.ts`: `'self'`, `https:`, loopback `http://localhost|127.0.0.1|[::1]:*`, IDE schemes `vscode:`/`cursor:`/…) — browser defense-in-depth, not the gate (the gate is registered-`redirect_uri` match + S256 PKCE + operator consent); add new custom schemes there only when onboarding. (2) **Bind-or-mint at consent** — an unbound client (no `oauth_clients` row; absence == unbound) gets a pick-or-mint-agent card; "allow" writes the binding row, then `props.agentId` is re-derived from the binding, never a form, before `completeAuthorization`. (3) **Login-from-`/authorize`** — an unauthed requester gets `/login?next=<this url>`. The POST ladder `authorizePostOperator` is two-rung (pasted `operator_token` → synthetic Bearer, CSRF-exempt; else session cookie + `csrf_token` field), NOT `requireOperator` (its `X-CSRF-Token` header can't come from a no-JS form); it and `handleRevokeForm` deliberately stay two-rung while `authorizeOperatorForm` has three — loosening auth on consent or revoke is an operator decision. Every consent-shaped card renders JUDGEABLE CLIENT IDENTITY (`renderClientIdentity`): with open DCR the consent screen is the only human gate, and a blank card is one Allow from fleet-wide authority. Ordering is load-bearing: callback address first (the only unforgeable signal, provider-matched against registered URIs) with trailing host labels emphasized and leading ones muted (`emphasizeHostTail`, so `claude.ai.evil.example` can't read as `claude.ai`); `clientName` marked as a self-reported claim; then `client_id`, registration age (red under 10 min — a just-minted client reached via a link is the attack signature), client type (public/confidential, labelled never flagged; native CLIs must be public per RFC 8252). `logoUri`/`clientUri`/`tosUri`/`policyUri` are deliberately not rendered (phishing aid, not evidence). No per-vendor allowlist in rendering: `describeCallback` classifies by scheme + loopback-ness, and the "on THIS machine" framing is reserved for `IDE_CALLBACK_SCHEMES` + exact `localhost`/`127.x`/`[::1]` (a catch-all once rendered `evilapp://claude.ai` as a local handoff; `*.localhost` put a familiar name in the headline). Deny button first in DOM order (`flex-direction:row-reverse` restores layout) so Enter denies. `test/authorize-callback.test.mjs` pins these as attacks.
- **Door B (static `awh_` bearer)** - same key shape as `POST /d`; plumbed into the OAuth wrap as `resolveExternalToken` so one `apiRoute` covers both transports; `agentId` from `authenticateAgent` (HMAC-under-pepper + `revoked_at` check on `agent_keys`); `clientId: null` explicitly - an `awh_` key is not an OAuth grant, so there is no client to attribute (never invent a sentinel).

**Operator browser session (`src/session.ts`) — a SECOND door onto the operator check, not a third agent door.** The operator is separate (`authenticateOperator` = constant-time compare vs `OPERATOR_TOKEN`); the session lets them log in once (`GET/POST /login`, `/logout`, `src/login.ts`); browser-only — `/mcp` never consults these cookies. Stateless signed cookie, no D1/KV/migration: `awh_session = base64url({v,iat,exp,csrf}) "." HMAC(payload, signingKey)`, `signingKey = hmacSha256Hex("awh-session-signing/v"+EPOCH, OPERATOR_TOKEN)` — derived from `OPERATOR_TOKEN` on purpose (not `HMAC_PEPPER`): rotating the token must end every session. Two invalidation levers, both changing `signingKey`: bump `SESSION_EPOCH` (`[var]`, default `"1"`) or rotate `OPERATOR_TOKEN`. `authenticateOperatorRequest` resolves Bearer-first then cookie; the shared `requireOperator` (used by `admin.ts`/`admin-oauth.ts`/`DELETE /d/:id`) returns 401/403, enforcing CSRF (`403 csrf_failed`) only when authed via cookie + unsafe method — Bearer callers are CSRF-exempt, so programmatic/curl is unchanged.

**Operator console (`src/console.ts`, issue #22) — the server-rendered admin UI.** No-JS HTML under `/admin/console/*` (bare `GET /admin` 302s there), authed by the operator browser session — logged-out gets a sign-in card, not an existence oracle. UI layer ONLY: every console POST goes through the form-field CSRF ladder (`authorizeOperatorForm`, NOT `requireOperator` — a no-JS `<form>` can't send `X-CSRF-Token`), and every write reuses the `*Core` workers behind the JSON `/admin/*` handlers (wire bytes unchanged). Pages: dashboard (live-doc/agent counts, storage bar, and the #57 `countPendingPromotionCore` "pending promotion" stat linking to the review queue), agents, documents (`?q=`/`tag`/`slug`/`cursor`/`limit` filters, a Public/Private badge, and `visibility`/`publication` `<select>`s over the same `parseHttpListParams` the JSON doors use; `?visibility=public&publication=pending` is the one-click "Review queue" link, over the shared `publicationClause` so count and link can't drift), audit (`/admin/console/audit`, the 0020 ledger newest-first, same filters as the JSON twin; READ-ONLY and must stay so — a console control that could edit or clear an append-only table would be the one thing able to make the record lie), maintenance. Minted keys/secrets show in a one-shot disclosure card (rendered once, never logged). POST-not-DELETE divergence: `POST /admin/console/agents/revoke`, `/keys/revoke`, `/oauth-clients/delete` twin `DELETE /admin/agents/:id`, `/admin/keys/:id`, `/admin/oauth-clients/:id` — a no-JS form can only GET/POST, so the target id rides a form field.

**Shared write path: `src/core.ts`.** HTTP (`POST /d`, `PUT /d/:id`) and MCP share the publish/update/edit/read/read-text/revoke/list/find-by-slug/search cores. Sanitization runs exactly once, inside core — new write surfaces route through core, never duplicating the sanitize → cap-check → R2 → D1 sequence. `editDocumentCore` (MCP `edit_document` only, no HTTP `PATCH`) loads retained source S via `readDocumentSourceCore`, applies the edits (pure `src/edit.ts`), then delegates to `updateDocumentCore` with the doc's own `source_format` (hardcoding `"html"` fed Markdown to the identity pipeline and corrupted silently). Match is against the STORED source; the response adds a `replacements` count. An OMITTED `expected_version` on `edit_document` defaults to the version the source was read at (unlike `update_document`, where omission is a clobber) — otherwise an unguarded write silently reverts anything committed since the read; the agent gets a retryable `version_conflict`. `source_r2_key IS NULL` hard-fails `source_unavailable`, no fallback to H. **`updateDocumentCore` collapses an IDENTICAL re-write to a no-op (contract `2.1.0`):** when `sha256Hex(prep.sourceBytes)` equals the current version's `source_sha256` AND `sanitizer_v` + `source_format` match AND resolved title/description/tags/slug equal stored, it returns `unchanged: true`, `version = current_ver`, writing NOTHING (no version row, R2 blobs, FTS/link rows, vector re-embed or `updated_at` touch; `prior_source_*` ride the `current_ver` join). It exists because a `PUT` retry forked the version chain (one agent re-pushed an identical body every 30 min for ~1000 versions). Four rules: (1) keyed on source S, never H (a missed collapse is harmless; a false one swallows an edit); (2) `sanitizer_v` is part of the key, so `sanitizer_version()` is a correctness dependency — a byte-affecting allowlist or `markdown_to_html` change without a bump suppresses a needed re-render; (3) it sits AFTER the `version_conflict` check and slug lock; (4) it compares against `current_ver` only, never `published_ver`. ALL-OR-NOTHING (a metadata-only change writes a full version) so `unchanged` can't lie; pre-0015 rows (`source_sha256 IS NULL`) self-arm after one write; `publishDocumentCore` is never collapsed. Covered by `test/e2e/no-op-collapse.sh`. Listing-row reads share `LISTING_SELECT_COLUMNS`/`LISTING_JOINS` — add a `DocumentListing` column there once and list/find-by-slug/search all follow. Wire-shaping lives in `src/wire.ts`: core returns `{ ok: true, … }`; `toWriteResponse`/`toEditResponse`/`toRevokeResponse` (typed against `contract.ts`) are the ONE copy used by HTTP and MCP — call the mapper, never re-hand-list fields.

**Text-read path runs at READ time, not write.** `readDocumentTextCore` pipes the sanitized HTML through `htmlToMarkdown` (same WASM module as `sanitize`, separate export); no per-version markdown cache. Derived from sanitized H, so the text channel can't surface anything the sanitizer stripped. The `.src` blob is a separate read surface: `readDocumentSourceCore` fetches unsanitized S and re-runs the advisory pass (markdown-or-identity → sanitize → `detectAdvisories`), so a source-read carries `unsanitized: true` + `stripped[]`/`will_not_render[]` — divergence surfaced, never silent. Source-read is credential-gated via `requireReader` (operator OR agent, operator ≥ agent, never anonymous): any agent key already reads/overwrites every doc, so source discloses no extra authority, and the operator must never rank below an agent (an earlier `authenticateAgent`-only gate locked the operator out). Render stays H-only, never serves S. Exception: `documents_fts` is populated at WRITE time via the same `htmlToMarkdown` — the sole storage of body-as-text, only to feed BM25; reads re-derive fresh from R2, and the `converter_v` stamp signals drift.

**Two security layers (in order):**
1. **Sandbox + strict CSP at render** (`src/serve.ts`): `GET /d/:id` returns a tiny shell with `<iframe sandbox>` (empty = all restrictions on); `GET /d/:id/raw` is what the iframe loads under `default-src 'none'` + `frame-ancestors 'self'`. Two URLs is deliberate - `frame-ancestors` is header-only, so the bytes must come from an HTTP response, not `srcdoc`. The load-bearing wall.
2. **Ammonia-WASM sanitization at write** (`sanitizer/src/lib.rs` -> `src/sanitizer.ts`): strips `<script>`, `<meta http-equiv>`, `<iframe>`, dangerous URL schemes, inline event handlers. Cheap insurance behind the CSP wall (covers `<meta refresh>`, which CSP can't). `<style>` blocks ALLOWED through (since v1.4; current stamp `ammonia-v1.7`): the sanitizer does NOT parse CSS (verbatim passthrough, as with inline `style="…"`) - CSS defense is Wall 1, not the allowlist (docs/design/style-support-design.md). `sanitize()` also runs one narrow post-pass over `clean()`'s output - the `target="_blank"` splice (new-tab convention); everything else is ammonia's parse-and-reserialize.

Invariant `visibility='public'` ⇒ `published_ver IS NOT NULL`, held at four edges — `publishDocumentCore` binds at public birth, `setDocumentVisibilityCore` runs `published_ver = coalesce(published_ver, current_ver)` in the SAME statement as the flip, `revokeDocumentCore` nulls it, the migration covers history. A POINTER, not a fourth state axis: a private doc may carry one (staged), and flipping back to private leaves it. Status is the third axis (revoked = existence, visibility = anonymous read, status = currency); tags are classification like slug. `0019` `versions.author_client_id` (issue #63): the OAuth `client_id` behind the write, one grain finer than `author_agent_id`. Nullable, no default, NOT backfilled — three honest NULL readings (Door B, operator, pre-0019 legacy); only Door A writes non-NULL. **No FK/CHECK/index**: an FK's `ON DELETE SET NULL` would erase the trail exactly when it matters — a dangling id is the correct reading. Attribution only; appears in no access decision. Surfaced as `VersionListing`/`McpHistoryEntry.author_client_id`, `DocumentListing.current_author_client_id` (hence `SearchHit`/`PackDocument`), the MCP `read_document` envelope and the manage page's Client column. `0020` `audit_events` (issue #62): the append-only operator ledger — `id`/`at`/`kind` (CHECK-pinned; mirrored by `AuditKindSchema`, pinned to the SQL by `test/audit.test.mjs`)/`principal_kind`/`agent_id`/`client_id`/`key_id`/`document_id`/`outcome`/`detail` (small scalar JSON)/`request_id`, index `(at DESC, id DESC)`. `document_id` holds the **`public_id`, NOT `documents.id`** — read by a human holding a URL, it must survive the row being revoked and purged. No FK anywhere (0019's reasoning); no retention sweep in v1 (a prune verb would take `POST /admin/keys/prune`'s shape, never a TTL). Semantics + never-log list: the Audit-ledger paragraph. R2 (`DOCS`): two blobs per version — sanitized render H at `<docId>/v<n>-<nonce>`, retained source S at the `.src` sibling. Keys are per-write-ATTEMPT (nonce = 16 CSPRNG bytes via `newPublicId()`), not per-`(docId, versionNo)`: two concurrent updates both compute `nextVer = current_ver + 1`; one batch wins the PK and the loser's rollback once deleted the WINNER's bytes — per-attempt addresses mean it deletes only its own. Never re-derive an R2 key; every reader uses `versions.r2_key`/`source_r2_key`. Source bytes count toward the cap (`checkStorageCap` SUMs `size_bytes` + `source_size_bytes`, NULL→0). `versions` rows are append-only and survive revoke as audit trail (only R2 bytes are purged). KV (`OAUTH_KV`) belongs to the OAuth provider library. Vectorize (`VECTORIZE`) + Workers AI (`AI`) back semantic search (vector-search-design.md): `slopcafe-docs` index (name per-deployment via the binding), 1024-dim cosine, N chunk vectors per doc keyed `${documents.id}#${i}`, model `@cf/qwen/qwen3-embedding-0.6b`; no D1 migration (the chunk ID yields the doc id; the fixed `#0…#${MAX_CHUNKS-1}` range-delete handles shrinkage); sole metadata `preview`. Sync is best-effort, eventually-consistent, OUTSIDE the D1 batch. **Revoke:** `documents.revoked_at` flips before the R2 delete (unreachable instantly even if R2 hangs); the same batch clears + tombstones the slug, deletes the FTS row, drops outbound `document_links` and stamps `updated_at`; the chunk-vector delete rides `ctx.waitUntil` (index reclaim, not the kill switch — the read-path re-join enforces `revoked_at is null` regardless). The purge is IDEMPOTENT: the R2 delete runs post-batch, chunked under R2's 1000-key limit (2 keys/version), failures throw — re-issuing the revoke IS the recovery. A second `DELETE` on a revoked doc returns `200` and RE-RUNS the purge, skipping the D1 batch; only an unknown/malformed `public_id` 404s. Don't "fix" that back to a 404 — it would claim a retry is pointless while unsanitized `.src` bytes stay resident.

**Audit ledger (`src/audit.ts`, migration 0020, issue #62).** Append-only D1 record of security-relevant ACTS and REFUSALS: consent allow/deny, bind-or-mint, TOFU approval (`authorize.ts`); operator `/login` success/failure (`login.ts`, never the token); DCR `client_registered`, `token_issued`/`token_denied`, `mcp_auth_failed` (the `withAudit` layer); agent-key mint/revoke/prune, agent kill, OAuth-client mint/delete (the admin cores); document revoke/visibility/promote/slug-redirect/release (the `core.ts` mutators); and `version_conflict`/`slug_locked` inside `updateDocumentCore` (the one point every door converges on, so `mcp.ts` is untouched). NOT recorded: successful tool calls/reads (traffic — Workers Logs) or content writes (`versions` attributes every one). `recordAudit(env, waitUntil, event)` is BEST-EFFORT and OUTSIDE every `META.batch()` — fires after the act commits, swallows + logs failures, never fails a request (the vector-sync posture; `waitUntil` is an optional trailing param threaded from `index.ts`). **The never-log list is enforced by construction:** `event` is a Zod discriminated union of named scalars — no `detail: object`, no rest spread — so no key/secret/`OPERATOR_TOKEN`/cookie/CSRF nonce/body/document content/`Authorization`/PKCE material can reach a row; `test/audit.test.mjs` walks the union's field names against the forbidden list as SUBSTRINGS (only `key_id` allowlisted — hence `credentials_revoked`, not `keys_revoked`; don't loosen the test). Adding a kind = a union member + `AuditKindSchema` + the 0020 CHECK, pinned together by that test. Read surface: `GET /admin/audit` (`requireOperator`, `parseAuditListParams`, `(at DESC, id DESC)`, filters `kind`/`agent_id`/`document_id`/`since`) + the READ-ONLY console page; no agent-door twin, and none may be added.

**Single-tenant trust model.** Any active agent key can `PUT` to any document — `core.ts` deliberately does not scope updates by `created_by`. Write cores take an `Author` (`{kind:"operator"} | {kind:"agent"; agentId; clientId?}`), never a bare `agentId` (0013): the operator is a first-class author, never a fake agent. `Author` is NOT `Principal` minus anonymous (0019, #63): only an author carries the optional OAuth `clientId` (from `AwhProps`, stamped on `versions.author_client_id`), because `resolvePrincipal` reads a request where no client id exists; `clientId` is optional so every HTTP-door `{kind:"agent",agentId}` literal still means "no client". `documents.created_by`/`created_by_kind` keep the creator (`created_by` NULL for operator-created docs); per-version writer columns per 0013/0019. The operator authors via `POST /admin/documents` / `PUT /admin/documents/:id`, same core path. `listDocumentsCore` shows the whole fleet to every caller (add a `createdBy?` core arg if per-agent scoping is ever needed). Agents can also CURATE — `PUT /d/:id/tags` + `PUT /d/:id/status` (`curateDocumentTags`/`curateDocumentStatus`, `requireReader`) and MCP `set_document_tags`/`set_document_status` — not a widening, since an agent key already replaces any document's entire content. **`visibility`, revoke and PROMOTION stay `requireOperator`, deliberately:** visibility is the boundary between fleet-private and anonymous-readable, revoke is irreversible, and promotion (`POST /admin/documents/:id/promote`, 0018) moves bytes ACROSS that boundary — an agent that could promote its own write would re-create the exfiltration path `published_ver` closes. No agent-reachable promote exists or may be added (no HTTP twin on `/d/`, no MCP tool, no `published_ver` input on a write tool — the same rule that keeps `visibility` out of every MCP input). Agents SEE the pointer (every MCP write/read envelope echoes `published_version`) to report "stored but not live yet"; they never move it. A new classification surface goes agent-side only after asking which side of THAT line it falls on: tags/status reach no anonymous surface; promotion is defined by reaching one. Unsanitized source bytes are at rest in R2 (the `.src` blob, 0008): credential-gated (operator or agent, never anonymous), never served to a browser — render stays H-only behind the iframe+CSP wall; `representation:"source"` widens only the ingestion-as-context surface, covered by the provenance tag + credential auth; revoke purges `.src` alongside H. **ONE operator-only path ASSERTS identity instead of minting it: the corpus restore (`POST /admin/restore`, `src/backup.ts`, #9)**, re-asserting `documents.id`/`public_id`/`version_no`/`created_at`/tombstones from a backup so shared `/d/<id>` links survive DR. Admissible on three grounds and nowhere else: `requireOperator` (no agent door exists or may be added — an agent asserting a `public_id` could squat any address); own-instance bytes (this deployment's `GET /admin/backup` export; key hashes are pepper-bound — same-deployment recovery, NOT portability, deferred 2026-09-03); and the render rule — **restored H is never trusted from the file**: every live version is re-derived from its restored S through `screenAndPrepare` under the CURRENT `sanitizer_v`, `size_bytes`/`source_sha256` recomputed (mismatch = `corrupt`; no S = `source_unavailable`, no legacy fallback), fresh nonced keys via `putVersionBlobs`. It never releases a slug tombstone (0009 wins; remedy `DELETE /admin/slugs/:slug`), and a page with any invalid line applies nothing. A backup file holds every `.src` plus the key hashes: as sensitive as the bucket and keys table together.

**Per-document visibility — a two-axis read model (migration 0011, issue #7).** Orthogonal to revoke: every document is `public` or `private`; `src/access.ts` is the single pure chokepoint. `canRead(principal, doc)` is top-down first-match-wins (revoked→false, operator→true, agent→true, anonymous→`visibility === "public"`); `resolvePrincipal` resolves operator → agent → anonymous. Visibility gates ONLY the anonymous browser surface (`serveShell`/`serveRaw`/`serveBySlug`/`serveHomepage`, enforced at the `serveRaw` chokepoint); the operator (cookie OR bearer) and any agent key read everything (`/text`, `/source`, MCP read/list/search, `listDocumentsCore`). A private doc denies as the same opaque 404 as missing/revoked — never a 401. New docs are born at `DEFAULT_DOCUMENT_VISIBILITY` ([var], default `"private"`), bound EXPLICITLY by the write path (the column's `DEFAULT 'public'` covers only legacy rows); the operator flips it via `POST /admin/documents/:id/visibility` or the Manage page (`setDocumentVisibilityCore`, no version bump). Visibility-CHANGE authority is a separate `requireOperator` check, deliberately OUT of `canRead`. ## Conventions and gotchas

- **`If-Match` is required on `PUT /d/:id`** (428 if missing). Send `"v<n>"` for optimistic concurrency or `*` to skip. Strong tags only; no weak tags, no multi-tag lists.
- **`POST /d` / `PUT /d/:id` accept `Content-Type: text/html` or `text/markdown`** (`text/x-markdown` too; else 415; gate `parseInputFormat`, `src/index.ts`). Markdown parses (CommonMark+GFM) to HTML pre-sanitize; stored bytes are always sanitized `text/html; charset=utf-8`; input path recorded in `versions.source_format`.
- **Optional `X-Content-SHA256` byte-exact integrity check on `POST /d` / `PUT /d/:id`** (`src/integrity.ts` via `readVerifiedBody`). Hashes the **raw body before sanitization**—verifies the wire, not the sanitizer; orthogonal to `modified`. Malformed header→400 `bad_integrity_header`; mismatch→422 `integrity_mismatch`. **HTTP-only by design** (companion to the `curl --data-binary @file` path): the hash must come from the deterministic tool streaming the file—no MCP equivalent. Rationale: `byte-exact-publish-design.md` (the 66–85 KB constraint is model regeneration of `content`, not transport).
- **Short-lived publish credentials (`agent_keys.expires_at`, 0007).** The byte-exact curl path needs a shell bearer connectors can't hold, so the MCP session mints it: `create_publish_credential` → `mintEphemeralKey` (`src/admin.ts`), a normal `awh_` key with non-NULL `expires_at` (default 15 min, max 60, clamped). `authenticateAgent` rejects expired like revoked (`isKeyExpired`); `expires_at = NULL` = never. No scope column — single-tenant; the key grants nothing beyond the session's authority. The minted `key` is the deliberate disclosure surface — never log it. **The `recipe` is NOT a secret** (issue #34): it references the key via `$AWH_KEY` (`export` once; space-prefix to skip shell history) so the token never reaches the curl command line — don't "re-harden" by interpolating `result.key` back in. Revoke early: `DELETE /admin/keys/:id`. Expired and revoked rows are never auto-deleted; `POST /admin/keys/prune` (#13) hard-deletes `expired` eagerly (self-revoking, near-zero audit value) while `revoked` REQUIRES `older_than_days` (a deliberate operator action, kept as audit trail) — never one retention rule for both.
- **Optional metadata on POST/PUT /d**: `X-Doc-Title`, `X-Doc-Description`, `X-Doc-Tags` (comma-separated), `X-Doc-Slug`; MCP write tools take the same fields. **Header values are read as UTF-8** (`decodeHeaderUtf8`, issue #31)—headers arrive as Latin-1 byte views (Fetch ByteString); undecoded non-ASCII = mojibake. Fatal-with-fallback: ASCII identity, valid UTF-8 recovered, a lone Latin-1 byte preserved as-is. Agents send non-ASCII literally, not entity-encoded (the sanitizer normalizes entities to UTF-8; only `& < > "` + `&nbsp;` stay encoded). On UPDATE an *omitted* field inherits (slug: the document's current); explicit `""` clears (title re-derives from H1; slug releases). Tags charset `[A-Za-z0-9_-]`—invalid chars silently stripped. Slug charset `/^[a-z0-9](?:[a-z0-9_-]{0,62}[a-z0-9])?$/`—invalid input **rejected** (`invalid_slug` 422), never sanitized (mutating a unique key could surprise-collide). Slug unique across live docs (partial UNIQUE INDEX); conflict→`slug_taken` 409. Bidi/zero-width strip on title only; description keeps bidi (never reaches the browser tab).
- **Slug AND tags live on `documents`, not `versions`** (tags since 0012): both survive updates/restores and never bump a version; slug changes are atomic claim-new + retire-old in one D1 batch. On revoke, rename or clear `documents.slug` goes NULL but is **NOT reusable** — retired into `slug_tombstones` (0009) forever; `/s/<slug>` → **410 Gone**, reclaim → `slug_retired` (issue #6: shared links must not silently change content). `documents.slug` is the live slug; claims check both via `resolveSlug`; a live-lookup miss consults `findSlugTombstoneCore` (410-vs-404); read/list queries pull slug from `d.slug`. **A retired slug can REDIRECT (0010, `slug_tombstones.redirect_to` = target `public_id`), but only LOUDLY:** rename auto-forwards to the same doc; the operator cross-redirects via `POST /admin/slugs/:slug/redirect`; never auto-followed — browser: click-through interstitial; agent: `409 slug_redirected` (HTTP) / `{redirected:true}` (MCP), opt-in via `follow_redirects`. Single-hop (dead target → 410). The target is additionally `canRead`-gated (`redirectTargetReadableBy`): to an anonymous caller an unreadable target is a dangling one — plain 410, never named. `resolveRedirectTarget` filters `revoked_at is null` but deliberately NOT `visibility` — **every caller gates the result itself**. Escape hatches: `DELETE /admin/slugs/:slug` force-releases a tombstone (the only un-retire path); `…/redirect` drops just the redirect. **An AGENT may not change the slug of a PUBLIC document — `slug_locked` (403), issue #43:** a rename is an immediate, un-promotable write onto an anonymous-readable address. Enforced once in `updateDocumentCore`, keyed on the resolved slug ACTION, not field presence: re-sending the existing slug is a no-op; rename and clear both lock (`invalid_slug`/`slug_taken`/`slug_retired` can fire first); via delegation one check covers `PUT /d/:id`, MCP `update_document`/`edit_document` and restore-with-slug; publish (a brand-new doc) and operator slug changes are exempt; content writes are unaffected — remedy: re-send without a slug field or ask the operator. `tags`/`status` were checked against this line and deliberately NOT restricted (neither reaches an anonymous surface). **The `slopcafe-docs-` prefix is RESERVED** (`RESERVED_SLUG_PREFIX`/`isReservedSlug`, `metadata.ts`; issue #4): every writer, agent AND operator, gets `invalid_slug` + `reason:"reserved_prefix"`, enforced once in `resolveSlug` behind an `allowReservedSlug` flag only the seeder passes — a hand-authored doc at one of these names would be indistinguishable to an agent following a tool description and would collide when the seeder ran.
- **Operator document-management page (`src/manage.ts`, #53) + browser login-link 404 (`src/serve.ts`).** `GET /d/:id/manage` (`serveManagePage`), cookie-session-gated, folds visibility/slug/tags/status/revoke forms plus read-only Version history and Link graph panels; logged-out → sign-in card with NO DB hit. **`GET /d/:id/revoke` (`serveRevokeConfirm`) resolves operator auth BEFORE any DB read**: an `Authorization`-carrying caller gets opaque `notFound()`; a plain browser gets the paste-the-token confirm card with no query — bytes identical for any id (a wrong id fails at POST). Shell topbar kebab = "Manage…". JSON twins in `admin.ts`: `setDocumentVisibility`/`setDocumentSlug` (no version bump; rename auto-forwards). **Browser login-link 404:** a valid `/d/:id` or `/s/:slug` 404s to a logged-out operator, so `notFoundBrowser` (+ `NOTFOUND_CSP`) returns an HTML 404 card with a Sign-in link via `/login?next=<requested URL>`; it never reads doc state — a private doc's 404 is byte-identical to a nonexistent one's. Wired into `serveShell`, `serveBySlug` (HTML-vs-plain by the `Authorization` header) and `serveRetiredSlug`'s no-tombstone case. Byte/HTML surfaces (`/raw`, `/v/:n/raw`, shells, the `/manage`+`/revoke` POSTs) keep plain `notFound()`; `/text`/`/source`/`/links` answer `notFoundJson()`.
- **Operator version history + restore-as-new-version.** No migration — `versions` retains every version's bytes (H + `.src`) until revoke purges. Surfaces: `GET /d/:id/v/:n` (+ `/v/:n/raw`), `authenticateOperatorRequest`-gated (Bearer OR cookie); the manage-page history table with per-row Restore (`POST /d/:id/restore`); JSON twins `GET /admin/documents/:id/versions` (→ `ListVersionsResponse`) and `POST /admin/documents/:id/restore` `{version:n}` (→ write envelope + `restored_from`), both `requireOperator`, over `listVersionsCore`/`restoreVersionCore`. Check `source_present` per row before offering Restore. An OPERATOR axis, not folded into `canRead`: a public doc's history is as operator-only as a private one's; non-operator → opaque 404. Agents read history via MCP `read_document` (`version`, `include_history`) — read-only, no agent restore. **Restore is always restore-as-NEW-version, never a `current_ver` rewind** (a rewind makes the next update collide on the `(document_id, version_no)` PK): `restoreVersionCore` re-publishes version N's retained S forward through `updateDocumentCore` — body + title/description/tags, keeping the current slug. A pre-0008 version with no source hard-fails `source_unavailable`, no fall-back-to-H; the manage table shows "no source". Covered by typecheck + the `wrangler dev` E2E.
- **The served-version rule is a security boundary; `src/served-version.ts` is its ONE copy (0018, issue #43).** `served = (visibility === 'public' && published_ver !== null) ? published_ver : current_ver` — deliberately with **no principal term**: a public doc serves its promoted version to anonymous, agent and operator alike (showing the operator newer bytes would blind the one person who can promote; staged work has its own address, `/d/:id/v/:n`); private renders current, since private is already the gate. **HTML byte path ONLY** — `GET /d/:id`, `/d/:id/raw`, `/s/:slug`, `/` (ETag, shell metadata and interstitial title follow the SERVED version). **Everything credentialed or machine-readable stays on `current_ver`, not an oversight to "align"**: `/text`, `/source`, `/links`, every MCP read/list/search, packs, FTS, vectors, the link graph, `/v/:n` — those callers read the whole corpus anyway, and a stale render would make `edit_document` patch bytes it can't see; the gate is about what LEAVES the fleet. It is a **leaf module** (no runtime imports; `Visibility` is `import type`) because `serve.ts` and `core.ts` both need it and the reverse edge is a cycle — a drifted second copy is a silent anonymous-disclosure hole. Two exports: `SERVED_VER_SQL` (alias the documents table as `d`; interpolated, names columns only) and `servedVersion(doc)`. **Every new render site routes through one of those two.** Gate `revoked_at is null` first (revoke nulls both pointers). `/d/:id/raw` emits `x-doc-current-version` for non-anonymous principals only (staged work's existence is never disclosed), because `/raw`'s ETag names the SERVED version and is no longer a valid `--if-match` preflight — writers prefer the header, ETag only when absent.
- **The machine-readable read routes answer JSON, not `text/plain`; their 404 may carry a shape hint.** `/d/:id/text`, `/d/:id/source`, `/d/:id/links` return `notFoundJson()` (`{error:"not_found", message}`) — their 401s/409s were already JSON. Opacity unchanged: missing/revoked/private/malformed-id answer identically for the same URL; only `message` varies, via the exported `idShapeHint(id, slugRoute)` — purely syntactic from the caller's own path segment, no DB read, never an existence oracle. A segment failing `PUBLIC_ID_RE` but valid as a slug names the conversion (`GET /d?slug=…`, plus `/s/:slug/text` where a slug twin exists); a well-formed `public_id` gets the bare message (a lowercase id also satisfies the slug charset, so "that isn't a public_id" would be wrong). Reused by `PUT /d/:id` and every `/admin/documents/:id/*` mutator (`documentNotFound`). NO auto-resolve of a slug in the id slot — blurring the two is how a shared `/s/<slug>` gets treated as an unguessable capability URL.
- **`version_not_found` is a first-class `ErrorCode`, emitted only behind an operator gate.** `POST /admin/documents/:id/restore` and `/promote` once reported a version miss as `404 not_found` with an optional `version` field — the discriminator between two misses with different remedies (give up vs pick another version) was a field's PRESENCE, invisible to a client switching on `error`. The split (2.0 ledger entry 7) gives the miss its own code with `version` REQUIRED; `not_found` is context-free again; status unchanged (404). **Hard rule: never emit this code on an anonymous-reachable surface** — safe on those two routes only because `requireOperator` already ran (the operator can enumerate `GET /admin/documents/:id/versions`), and MCP `read_document`'s `version` arg has surfaced the same token via `textError` all along; anywhere anonymous, "live doc but no such version" is the existence oracle every opaque 404 in `serve.ts` prevents. The same change declared `source_unavailable`'s optional `version` context (`ErrorBody` members are `additionalProperties: false`).
- **`GET /d/:id/text` and `/s/:slug/text` content-negotiate on `Accept`.** `application/json`→the `ReadTextResponse` envelope (body **plus** title/description/tags/slug/status/superseded_by); anything else (wildcard/no header) keeps the historical `text/markdown` body. `Vary: Accept` on both. Why: a metadata-less body pushed callers toward the `/source` shortcut—ingesting UNSANITIZED bytes as context. Negotiation, not a `/text.json` route: those URLs already negotiate (on `Authorization`); the shape existed in `contract.ts`.

Naming a resource at CREATION time is the opposite case and stays literal: `wrangler d1 create slopcafe-meta` in the setup guides, `database_name`/`bucket_name`/`index_name` in `wrangler.toml.example`. **Caveat:** within one config wrangler matches `database_name` BEFORE `binding`, and `d1 execute`—unlike `migrations apply`/`list`—has no config-miss guard, so a second `[[d1_databases]]` entry literally named `META`, or an invocation with no `wrangler.toml` in scope, can resolve somewhere unintended.
- **Wrangler version + Workers types.** `compatibility_date = "2026-05-26"` with `nodejs_compat` (also covers the agents MCP handler's `AsyncLocalStorage` plumbing). Types devDep is on `@cloudflare/workers-types@^5` matching `wrangler`'s peer.
- **The `overrides` block in `package.json` closes Dependabot alerts upstream won't; removing an entry silently re-opens a CVE.** Every npm alert here has been transitive; the one entry plain `npm install` can't reach is `@hono/node-server: ^2.0.5` (a MAJOR-bump fix the MCP SDK's `^1.19.9` pin couldn't take; since SDK `1.30.0` the range allows it, so the override is belt-and-suspenders). Transitives with semver-reachable fixes were healed by targeted `npm update <name>` — prefer that; override only when the fix sits outside the parent's declared range. Triage reachability first: `npx wrangler deploy --dry-run --outdir <dir>`, then read `index.js.map`'s `sources` — the Worker bundles only 8 npm packages (`@cfworker/json-schema`, `@cloudflare/workers-oauth-provider`, `@modelcontextprotocol/{core,core-internal,server}`, `agents`, `content-type`, `zod`); everything else in an alert is dev-tree (miniflare) or the v1 SDK's never-imported Express transports. `npm audit fix` does not work here (it dies on a pre-existing peer conflict in the `agents`→`@cloudflare/ai-chat`/`ai` chain); use targeted `npm update` + override, never `--force`/`--legacy-peer-deps`.
- **Secrets** (`HMAC_PEPPER`, `OPERATOR_TOKEN`) live in `.dev.vars` for local dev (gitignored) and `wrangler secret put` for production—never `[vars]` in `wrangler.toml`. `SESSION_EPOCH` is the exception: a non-secret rotation counter in `[vars]` (default `"1"`); bump it to invalidate all browser sessions. `CORS_ALLOWED_ORIGINS` is `[vars]` too (non-secret, empty/unset = CORS off — `src/cors.ts` bullet), as is `HOMEPAGE_PUBLIC_ID` (non-secret, empty/unset = placeholder at `/` — `src/serve.ts` bullet). Both are per-deployment state that must stay OUT of tracked source: `wrangler.toml` is gitignored precisely so this instance's values never ship to a fork.
- **App Links / Universal Links verification (issue #50) — off by default.** `GET /.well-known/assetlinks.json` (Android) and `GET /.well-known/apple-app-site-association` (iOS, `components` form covering `/d/*` + `/s/*`) let the operator's mobile app claim document URLs. Both anonymous, no DB read, `isCorsEligible` (public JSON, no principal — the `/docs*` reasoning). Driven by three `[vars]` — `APP_LINKS_ANDROID_PACKAGE`, `APP_LINKS_ANDROID_SHA256` (comma-separated colon-hex fingerprints), `APP_LINKS_APPLE_APP_ID` (`TEAMID.bundle.id`) — read through the SINGLE validator `appLinksConfig(env)` in `src/app-links.ts`. Android is all-or-nothing (either half missing or malformed disables the whole platform); unset/malformed and the route answers the SAME opaque 404 as any unmatched route — a fresh fork changes nothing. The issue's stated blocker was wrong: the OAuth provider intercepts only its two `/.well-known/oauth-*` paths; everything else under `/.well-known/` reaches `innerHandler`.
- **Every code file carries an SPDX header** (Apache-2.0, issue #15): `// SPDX-FileCopyrightText: 2026 Skylled / Kyle Bradshaw` then `// SPDX-License-Identifier: Apache-2.0` on every `.ts`/`.rs`/`.mjs` file; **a new code file MUST get it.** Deliberately NOT headered: `.md` (`skills/publishing.md` + the bundled `docs/` corpus are served byte-exact—a header would corrupt served bytes), `.sql` migrations, config (`wrangler.toml`, `tsconfig.json`, `package.json`).
