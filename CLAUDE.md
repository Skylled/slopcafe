# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> **Operator-instance specifics — forkers, read this.** This repo is the source for Kyle's `slopcafe.com` deployment. A few obligations below are tied to *that specific instance*, not to the code: the "re-publish the live Slopcafe copy in the same commit" rules and the hard-coded `public_id`/`slug` values (e.g. `slopcafe-http-api` → `0EtsEq6cnCeuOhBKO6ICzA`, the SOLO/PLATFORM spec ids, and the `slopcafe-*` design-note slugs) point at documents in Kyle's corpus on `slopcafe.com`. If you fork this and run your own deployment, treat those as *examples* — substitute your own slugs/ids or skip the mirror step entirely; nothing in the code depends on them. Everything else here (the architecture, the conventions, and the source-↔-`docs/` sync rules that don't mention Slopcafe) is instance-independent.

## Commands

Build / deploy / dev:
```sh
npm run dev            # wrangler dev — uses .dev.vars + local D1/R2
npm run typecheck      # tsc --noEmit
npm run build:wasm     # rebuild the Rust→WASM sanitizer (auto-run via predeploy)
npm run deploy         # rebuilds WASM then `wrangler deploy`
```

Tests:
```sh
npm test                  # sanitizer corpus + advisories + metadata + pagination + search + edit + integrity + auth + session + access + conditional + depth + vector + pack + contract + openapi
npm run test:sanitizer    # cargo test in /sanitizer (host target, not wasm)
npm run test:advisories   # node --experimental-strip-types test/advisories.test.mjs
npm run test:metadata     # node --experimental-strip-types test/metadata.test.mjs
npm run test:pagination   # cross-file ts import → uses test/register-ts-resolver.mjs (also covers the order/updated_since parse)
npm run test:search       # FTS5 query tokenizer (buildFtsMatchQuery) — pure function tests
npm run test:edit         # applyEdits find/replace logic (edit_document) — pure function tests
npm run test:depth        # maxNestingDepth pre-screen (the depth-bomb guard) — pure function tests
npm run test:pack         # context-pack pure logic (budget fill, manifest parser, link extractor)

# Run a single sanitizer test (Rust name match):
(cd sanitizer && PATH="$HOME/.cargo/bin:$PATH" cargo test rejects_script_tag)
```

Database (D1):
```sh
npm run db:migrate:local            # apply migrations to local D1
npm run db:migrate:remote           # apply migrations to remote D1
npm run db:console:local  "SELECT * FROM agents"
npm run db:console:remote "SELECT * FROM agents"
```

`predeploy` injects `$HOME/.cargo/bin` into PATH so `wasm-pack` resolves from a fresh shell. Rust toolchain (`rustup` + `wasm32-unknown-unknown` target + `wasm-pack`) is only required for `build:wasm`.

## Git workflow

When the operator says "commit your work" (or similar) without specifying a branch, **commit straight to `main`** — do not branch first. The operator deliberately delegates commits to the agent so the work shows up credited in the log; keep using the standard `Co-Authored-By` trailer. Still only commit/push when explicitly asked, and push only on explicit request.

## Architecture

**Single Worker, one origin.** `src/index.ts` exports an `innerHandler` doing exact-match route dispatch, and the default export is that handler wrapped in `@cloudflare/workers-oauth-provider` (see `src/oauth.ts`). The OAuth wrap intercepts `/mcp` (its `apiRoute`), validates the token, populates `ctx.props.agentId`, and dispatches to the same inner handler as `apiHandler`. Everything else (including `/authorize` and the `awh_`-bearer path on `/mcp`) goes to `defaultHandler`. **The inner handler is registered as both `apiHandler` and `defaultHandler`** — the only difference between the two paths is whether `ctx.props.agentId` is populated. The route table matches on `method === "GET"` (etc.) literally, so **`HEAD` is normalized to `GET` by the `withHeadSupport` wrapper** sitting *between* the OAuth wrap and `innerHandler` (`wrapWithOAuth(withHeadSupport(innerHandler))`): it re-issues the request as a `GET` (carrying the original headers, so the visibility/auth/`If-None-Match` gates are unchanged) and strips the response body, so `HEAD /d/:id/raw` answers with the `GET`'s `text/html`/`ETag`/CSP instead of falling through to the JSON `404` (GitHub issue #36). A private/missing doc still `HEAD`s as the same opaque `404`.

**Two auth doors converge on one identity (`AwhProps` in `src/mcp-auth.ts`):**
- **Door A (OAuth 2.1 + PKCE)** — one pre-registered client per agent. Bound mint via `POST /admin/agents/:id/oauth-clients`; or **unbound** mint via `POST /admin/oauth-clients` (KV client record, no `oauth_clients` row) with the agent chosen at consent. Clients can also **self-register via DCR** (`POST /register`, RFC 7591 — served by the provider library when `ENABLE_DCR` in `src/oauth.ts` is on; **public (PKCE-only) clients allowed** — `DISALLOW_PUBLIC_CLIENT_REGISTRATION = false`, required for native CLIs like Claude Code's `claude mcp add` which can't hold a secret; 90-day client TTL): a DCR client arrives unbound and rides the same bind-or-mint-at-consent path, which is what enables the paste-the-MCP-URL connect flow with no operator-minted client_id (docs/design/dcr-design.md, BUILT). Consent UI lives in `src/authorize.ts`; the operator approves with `OPERATOR_TOKEN` (or a browser session). Used by Cowork / claude.ai web / ChatGPT. `agentId` comes from the grant's `encryptedProps` (via `ctx.props`). **Every authorization response our code 302s to a client callback carries RFC 9207 `iss=<request origin>`** (SEP-2468, GitHub issue #46) — the allow path (bound consent and bind-or-mint converge on one `completeAuthorization`) and the deny redirect alike — stamped by the pure exported `appendIssParam` in `src/authorize.ts` (URL-API surgery: custom schemes and loopback both parse; overwrite-if-present so a future library-emitted `iss` can never duplicate or conflict — the provider does NOT emit it as of 0.8.2; pinned in `test/authorize-callback.test.mjs`). Error states that render HTML in place never reach the callback, so `iss` doesn't apply to them. **`/authorize` is operator-session-aware and offers three inline repairs** (all operator-gated, none disclose client state to non-operators): (1) **TOFU callback approval** — register an unregistered but allowlisted-host `redirect_uri` via `updateClient`; the allowlist is `APPROVABLE_CALLBACK_HOSTS` in `src/admin-oauth.ts` (the narrow **vendor-https TOFU** trust list — `claude.ai`/`claude.com`/`chatgpt.com`; `validateCallbackUri` in `session.ts` is the pure https-only gate). **This allowlist is NO LONGER coupled to the consent-page CSP `form-action`** (it used to be — that coupling is exactly what blocked native clients). `form-action` is now the standalone `CONSENT_FORM_ACTION_SOURCES` in `src/authorize.ts`, deliberately broad enough to cover *every legitimate OAuth callback shape* — `'self'`, `https:` (any vendor, no per-host list), `http://localhost|127.0.0.1|[::1]:*` loopback (RFC 8252 native/CLI clients), and IDE custom schemes (`vscode:`/`cursor:`/…) — because `form-action` is **browser defense-in-depth, not the access gate**: the real gate is the library's per-client registered-`redirect_uri` match + S256 PKCE + operator consent, so the form can only 302 to a provider-validated target. Add a new custom scheme there (only) when onboarding a client that uses one. (2) **Bind-or-mint at consent** — an *unbound* client (no `oauth_clients` row; needs **no migration** — absence == unbound) gets a pick-existing-or-mint-new-agent card; "allow" writes the binding row, then `props.agentId` is **re-derived from the binding** (never trusted from a form) before `completeAuthorization`. (3) **Login-from-`/authorize`** — an unauthed requester gets a `/login?next=<this url>` link, keyed on the requester's own auth state so it discloses nothing. The POST auth ladder (`authorizePostOperator`) is two-rung — pasted `operator_token` → synthetic Bearer/CSRF-exempt, else session cookie + `csrf_token` field — and does **not** call `requireOperator` (that wants an `X-CSRF-Token` header a no-JS form can't send). It and `handleRevokeForm` keep their own inline copies; the shared `authorizeOperatorForm` has since grown a third rung (see the session bullet below), and these two deliberately have not — loosening auth on consent and on an irreversible revoke is an operator decision, not a drive-by. **Every consent-shaped card renders JUDGEABLE CLIENT IDENTITY (`renderClientIdentity`), because open DCR means the consent screen is the only human gate:** anyone can `POST /register` a public client with their own `redirect_uri` and mail the operator an `/authorize` link, so a card that shows nothing is one Allow click from handing an attacker fleet-wide corpus authority. Ordering is load-bearing — the **callback address leads** (the ONLY unforgeable signal: it is where the code is physically delivered, and the provider matched it against the client's registered URIs), with its **trailing host labels emphasized and the leading ones muted** (`emphasizeHostTail`) so `claude.ai.evil.example` cannot read as `claude.ai`; `clientName` follows as an explicitly-marked *self-reported claim* (a self-registered client can call itself "Claude"); then `client_id`, registration age (red under 10 min — a client minted seconds ago and reached via a link is the attack's signature), and client type (public/confidential — **labelled, never flagged**, since native CLIs must be public per RFC 8252). `logoUri`/`clientUri`/`tosUri`/`policyUri` are deliberately NOT rendered — an attacker-supplied image or link is a phishing aid, not evidence. There is **no per-vendor allowlist in the rendering path** (that is what lets Claude, ChatGPT and a loopback CLI all work): `describeCallback` classifies purely by scheme + loopback-ness, and the friendly "an application on THIS machine" framing is reserved for `IDE_CALLBACK_SCHEMES` + **exact** `localhost`/`127.x`/`[::1]` — an open catch-all rendered `evilapp://claude.ai` as a local handoff, and `*.localhost` let an attacker put a familiar name in the bold headline. The Deny button is emitted FIRST in DOM order (with `flex-direction:row-reverse` restoring the visual layout) so a form's implicit Enter-key submit **denies** rather than grants. `test/authorize-callback.test.mjs` pins these as attacks; the two pure helpers are exported solely for it.
- **Door B (static `awh_` bearer)** — same key shape `POST /d` uses. Plumbed into the OAuth wrap as `resolveExternalToken` so a single configured `apiRoute` covers both transports. `agentId` comes from `authenticateAgent` (HMAC-under-pepper + `revoked_at` check on `agent_keys`).

**Operator browser session (`src/session.ts`) — a SECOND door onto the *operator* check, not a third agent door.** The two doors above authenticate *agents*; the operator is separate (`authenticateOperator` = constant-time compare vs `OPERATOR_TOKEN`). The session layer lets the operator log in once in a browser (`GET/POST /login`, `GET/POST /logout` in `src/login.ts`) instead of pasting the token on every action. It is HTTP/browser-only — **`/mcp` never consults these cookies** (the OAuth wrap owns it), and **no MCP tool/`/mcp` behavior changes**. It's a **stateless signed cookie**, no D1/KV/migration: `awh_session = base64url({v,iat,exp,csrf}) "." HMAC(payload, signingKey)`, where `signingKey = hmacSha256Hex("awh-session-signing/v"+EPOCH, OPERATOR_TOKEN)`. The signing key is derived from `OPERATOR_TOKEN` **on purpose** (not `HMAC_PEPPER`): the session authenticates the operator principal, so rotating the token must end every session — don't "fix" this to the pepper. Two invalidation levers, both of which change `signingKey`: bump `SESSION_EPOCH` (a `[var]`, the cheap "log everyone out" knob — defaults to `"1"` via `sessionEpoch(env)`) or rotate `OPERATOR_TOKEN`. `authenticateOperatorRequest` resolves **Bearer-first then cookie**; the shared async `requireOperator` (in `session.ts`, used by `admin.ts` / `admin-oauth.ts` / `DELETE /d/:id`) returns 401/403 and enforces CSRF (`403 csrf_failed`) only when authed **via cookie + unsafe method**. Bearer-authed requests are CSRF-exempt — so every programmatic/curl caller is unchanged.

**Operator console (`src/console.ts`, GitHub issue #22) — the server-rendered admin UI.** A no-JS HTML console under the **`/admin/console/*`** namespace (bare `GET /admin` 302-redirects to `/admin/console`), authed by the **operator browser session** (cookie + CSRF) above — a logged-out caller gets a sign-in card, not an existence oracle. It is a UI layer ONLY: every console POST routes through the **form-field CSRF ladder** (`authorizeOperatorForm`, NOT `requireOperator` — a no-JS `<form>` can't send the `X-CSRF-Token` header `requireOperator` wants), and every write reuses the same `*Core` worker the JSON `/admin/*` handlers call (`mintAgentCore` / `mintAgentKeyCore` / `revokeAgentCore` / `revokeKeyCore` / `listAgentsCore` / `listAgentKeysCore` in `admin.ts`; `createOAuthClientCore` / `createUnboundOAuthClientCore` / `deleteOAuthClientCore` / `listBoundClientsCore` in `admin-oauth.ts`). **The JSON `/admin/*` API is UNCHANGED** — the `*Core` refactor kept its wire bytes byte-identical. The console pages are the dashboard, agents (list + detail with key minting), documents (list with `?q=`/`tag`/`slug`/`cursor`/`limit` reusing the existing list/search core filters + a Public/Private **badge** only — no server-side visibility filter), and maintenance (vectors backfill). A freshly minted agent key or OAuth-client secret is shown in a **one-shot disclosure card** (rendered once, never logged — same discipline as the MCP minted key + the OAuth token). **POST-not-DELETE divergence:** several console routes (`POST /admin/console/agents/revoke`, `/admin/console/keys/revoke`, `/admin/console/oauth-clients/delete`) are POST twins of JSON `DELETE`s (`DELETE /admin/agents/:id`, `/admin/keys/:id`, `/admin/oauth-clients/:id`) because a no-JS HTML form can only GET/POST — the target id rides a form field (`agent_id` / `key_id` / `client_id`), not the path.

**Shared write path: `src/core.ts`.** Both HTTP (`POST /d`, `PUT /d/:id` in `src/index.ts`) and MCP (`src/mcp.ts` tools) call `publishDocumentCore` / `updateDocumentCore` / `editDocumentCore` / `readDocumentCore` / `readDocumentTextCore` / `revokeDocumentCore` / `listDocumentsCore` / `findDocumentBySlugCore` / `searchDocumentsCore`. **Sanitization runs exactly once, inside core**, regardless of door. If you add a new write surface, route it through core — never duplicate the sanitize → cap-check → R2 → D1 sequence. `editDocumentCore` is the find/replace surface (MCP `edit_document` only — no HTTP `PATCH`): it does NOT re-implement the sequence — it loads the **retained source S** via `readDocumentSourceCore`, applies the string edits (pure logic in `src/edit.ts`), then DELEGATES the write to `updateDocumentCore` passing the doc's **own** `source_format` (no longer hardcoded `"html"` — getting this wrong feeds a Markdown source to the HTML identity pipeline and corrupts *silently*), so there's exactly one copy of the sanitize→cap→R2→D1→FTS batch. Match is against the STORED **source** (Markdown for md docs, HTML for html docs — so a Markdown doc edits its Markdown and the reader theme survives by construction); the response adds a `replacements` count so an agent can tell "patch landed" from "sanitizer normalized." **An OMITTED `expected_version` on `edit_document` is NOT a clobber** (unlike `update_document`, where it is): it defaults to `current.version_no` — the version the source was actually read at — because an edit writes a whole body forward from a base revision the *server* chose, so an unguarded write would silently revert anything committed between the source read and the update while cheerfully reporting `replacements: 1`. The agent sees a `version_conflict` it already knows how to retry. A source-unavailable doc (un-backfilled, `source_r2_key IS NULL`) hard-fails with `source_unavailable` — no fallback to H. **`updateDocumentCore` collapses an IDENTICAL re-write to a no-op** (contract `2.1.0`): when the incoming `sha256Hex(prep.sourceBytes)` equals the current version's `source_sha256` AND `sanitizer_v` + `source_format` match AND the resolved title/description/tags/slug all equal what's stored, it returns `unchanged: true` with `version = current_ver` having written NOTHING — no version row, no R2 blobs, no FTS/link rows, no vector re-embed, and no `updated_at` touch (a no-op is not a change). The three `prior_source_*` columns ride the existing `current_ver` join, so the gate costs zero extra round trips. It exists because `PUT` was not idempotent — a retry after a lost response forked the version chain, and one mis-programmed agent re-pushed an identical body every 30 minutes for ~1000 versions. Four rules it must keep: (1) it is keyed on the **source S**, never the render H — S is what `/source`/`edit_document`/restore operate on, and a missed collapse is harmless while a false one silently swallows an edit; (2) `sanitizer_v` is part of the key, which promotes `sanitizer_version()` from a provenance stamp to a **correctness dependency** — a byte-affecting change to the allowlist OR to `markdown_to_html`'s pulldown-cmark ingress that lands without a bump suppresses a re-render that should happen (the rule is now written on `sanitizer_version()` itself); (3) it sits AFTER the `version_conflict` check and AFTER the slug lock, so a stale base still conflicts and a public-doc rename still gets `slug_locked`; (4) it compares against `current_ver` **only, never `published_ver`** — collapsing against the published pointer would swallow an agent's newest bytes on a doc awaiting promote. It is deliberately ALL-OR-NOTHING (a metadata-only change writes a full version) so `unchanged` can't lie; a classification-only fast path is a separate decision. Legacy pre-0015 rows have `source_sha256 IS NULL` so the gate can't fire — it self-arms after one write. **`publishDocumentCore` is never collapsed** and hard-codes `unchanged: false`. Covered by `test/e2e/no-op-collapse.sh` (no D1 harness in the unit suite). Listing-row reads (`listDocumentsCore`, `findDocumentBySlugCore`, and `searchDocumentsCore`) share `LISTING_SELECT_COLUMNS` / `LISTING_JOINS` constants so the projection stays in lockstep — when adding a column to `DocumentListing`, update those two constants once and all three surfaces follow. **Wire-shaping the success Result is also centralized (`src/wire.ts`, Phase 2b):** core returns `{ ok: true, … }`-tagged Results; the on-the-wire JSON strips that `ok` (revoke renames it `revoked`). `toWriteResponse` / `toEditResponse` / `toRevokeResponse` are the ONE copy of that strip (typed against `WriteResponse`/`EditResponse`/`RevokeResponse` in `contract.ts`), used by both HTTP (`createDocument`/`updateDocument`/`revokeDocument` in `index.ts`) and MCP (`publish_document`/`update_document`/`edit_document` in `mcp.ts`) — don't re-hand-list those fields in a handler; call the mapper.

**Text-read path runs at READ time, not write.** `readDocumentTextCore` fetches the sanitized HTML and pipes it through `htmlToMarkdown` (same WASM module as `sanitize`, separate exported function). No per-version markdown cache in v1 — the parse is single-digit ms for typical docs and is dwarfed by the R2 GET it shares. The markdown text-read derives from the sanitized **H** blob; conversion always runs on the *cleaned* bytes so the text channel can't surface anything the sanitizer stripped. **The retained source `.src` blob is a separate read surface, not part of this path:** `readDocumentSourceCore` fetches the unsanitized **S** (the bytes as submitted) and re-runs the advisory pass on it (markdown-or-identity → sanitize → `detectAdvisories`) so a source-read carries `unsanitized: true` plus `stripped[]`/`will_not_render[]` — "the live render differs from this source here" is surfaced, never silent. Source-read is **credential-gated — operator OR agent (operator ≥ agent), never anonymous, never public** (the `requireReader` gate in `serve.ts`, which refuses only an anonymous principal): in this single-tenant whole-fleet model any active agent key already reads and overwrites every doc, so source discloses no authority the caller lacks — and the operator, the apex principal, must never rank below an agent (an earlier build gated `/source`+`/text` on `authenticateAgent` alone and so locked the operator out entirely). Render path stays H-only and never serves S. **Exception:** the FTS5 search index in `documents_fts` is populated at WRITE time using the same `htmlToMarkdown` call — the FTS shadow tables are the sole storage of the body-as-text for search. The read endpoint still re-derives fresh from R2 on each call (no D1 dependency for the markdown view); the FTS write-time copy is a separate, write-only side channel that only exists to feed BM25 ranking. The two can drift by at most one converter-version step if the converter changes between an old write and a new read — acceptable, and the `converter_v` stamp on the read response signals when it's happened.

**Two security layers (in order):**
1. **Sandbox + strict CSP at render** (`src/serve.ts`). `GET /d/:id` returns a tiny HTML shell with `<iframe sandbox>` (empty = all restrictions on); `GET /d/:id/raw` is what the iframe loads under `default-src 'none'` + `frame-ancestors 'self'`. Two URLs is deliberate — `frame-ancestors` is header-only, so the bytes must come from an HTTP response, not `srcdoc`. **This is the load-bearing wall.**
2. **Ammonia-WASM sanitization at write** (`sanitizer/src/lib.rs` → `src/sanitizer.ts`). Strips `<script>`, `<meta http-equiv>`, `<iframe>`, dangerous URL schemes, inline event handlers. Cheap insurance behind the CSP wall (covers e.g. `<meta refresh>` which CSP can't). **`<style>` blocks are ALLOWED through** (since sanitizer v1.4; the current stamp is `ammonia-v1.6`): the sanitizer does NOT parse the CSS (verbatim passthrough), exactly as it never parsed inline `style="…"` attrs — defense against CSS vectors is Wall 1 (the render-time CSP + iframe sandbox), not the allowlist (docs/design/style-support-design.md). `sanitize()` also runs one narrow **post-pass over `clean()`'s output** — the `target="_blank"` splice (see the new-tab convention below); everything else is ammonia's own parse-and-reserialize.

**Storage model.** D1 (`META` binding) holds the metadata — see `migrations/0001_init.sql` for `agents`, `agent_keys`, `documents`, `versions`; `0002_oauth_clients.sql` for `oauth_clients` (client_id ↔ agent_id join); `0003_source_format.sql` for `versions.source_format`; `0004_document_metadata.sql` for `versions.title` / `description` / `tags` (JSON-encoded array; NULL when unset — but `tags` was later **lifted to `documents.tags` and dropped from `versions` in 0012**); `0005_document_slug.sql` for `documents.slug` + partial UNIQUE INDEX where slug IS NOT NULL; `0006_documents_search.sql` for the `documents_fts` FTS5 virtual table (one row per live document, columns `document_id UNINDEXED, title, description, tags, body` with porter+unicode61+remove_diacritics tokenizer — **the `tags` column was dropped in 0012**, leaving `document_id, title, description, body`); `0007_key_expiry.sql` for `agent_keys.expires_at` (NULL = never; non-NULL only on the short-lived publish credentials minted by `create_publish_credential`); `0008_source_retention.sql` for `versions.source_r2_key` + `versions.source_size_bytes` (both nullable, no default — NULL = un-backfilled/legacy, the loud presence-flag `editDocumentCore`/`readDocumentSourceCore` hard-fail on with `source_unavailable`, never a legacy fallback); `0009_slug_tombstones.sql` for the `slug_tombstones` table (slug PK, document_id, retired_at, reason) that makes a claimed slug semi-permanent — reversing 0005's "released on revoke" (GitHub issue #6); `0010_slug_redirect.sql` adds `slug_tombstones.redirect_to` (target `public_id`) for the loud operator/rename redirect; and `0011_document_visibility.sql` adds `documents.visibility` (`public`|`private`, CHECK-pinned — column `DEFAULT 'public'` backfills legacy rows so already-shared docs keep serving, but new docs are born EXPLICITLY at `DEFAULT_DOCUMENT_VISIBILITY` ([var], default `"private"`), so the column default only ever covers pre-migration rows; GitHub issue #7); and `0012_document_tags.sql` **lifts `tags` from per-version to document-level** — adds `documents.tags` (backfilled from each doc's current version), `DROP`s `versions.tags`, and rebuilds `documents_fts` WITHOUT its `tags` column (the body text is carried through a temp table since it's WASM-derived and lives only in the FTS index); and `0013_authorship.sql` records the **author principal** so the operator is a first-class author rather than a fake agent — `documents.created_by_kind` (the creator's kind, `agent`|`operator`, CHECK-pinned, `DEFAULT 'agent'` backfills legacy) plus per-version `versions.author_kind` + `versions.author_agent_id` (the **queryable** writer, replacing the R2-customMetadata-only writer tag; legacy rows default to `agent`/NULL — the true historical writer survives only in customMetadata, not backfilled), so an operator-authored doc/version is honest and a document's full per-version author list is queryable; and `0014_document_status.sql` adds the **lifecycle axis** — `documents.status` (`active`|`deprecated`|reserved `archived`, CHECK-pinned, `DEFAULT 'active'` is both backfill and product default) plus `documents.superseded_by` (a replacement `public_id`, the document-level analogue of `slug_tombstones.redirect_to` — loud, never auto-followed, single-hop, live-target/no-self validated; GitHub issue #21); and `0015_source_sha256.sql` adds `versions.source_sha256` (nullable, no default — NULL = pre-0015/un-backfilled, same presence-flag posture as the 0008 source columns), the SHA-256 of the retained source S the Worker stamps at write time (`sha256Hex(prep.sourceBytes)` — the *same* bytes `X-Content-SHA256` hashes, so for a byte-exact publish it equals the publisher's `sha256sum file`). Surfaced as `current_source_sha256` on listing rows + `source_sha256` on the write response and source-read so an agent can confirm a local copy is still the current source and skip a source re-read before an edit (GitHub issue #35; ergonomics only — gates nothing); and `0016_document_links.sql` adds the **link graph** (GitHub issue #40) — the `document_links` table (`src_doc_id`, `position`, CHECK-pinned `target_kind` `public_id`|`slug`, `target_value`; PK on the (src, kind, value) triple + a `(target_kind, target_value)` index): one row per distinct on-platform link in a doc's CURRENT render, extracted at write time from H via the same `extractOutboundLinks` packs use, with the target stored as the RAW addressed name (late binding — resolved at read time by `documentLinksCore` into `live`/`redirected`/`retired`/`revoked`/`missing`), synced inside the same `META.batch()` as the FTS row (see the link-sync convention below); and `0017_document_updated_at.sql` adds `documents.updated_at` — the **modification-time axis** that turns `list_documents` into a change feed. Every mutator stamps it write-path-locally (no triggers): the four write cores, all four no-version-bump classification mutators (`setDocumentTagsCore`/`setDocumentSlugCore`/`setDocumentVisibilityCore`/`setDocumentStatusCore` — the whole reason it lives on `documents` and not `versions`), and `revokeDocumentCore` on the kill itself. `NOT NULL` with a deliberately absurd `'1970-…'` constant default (SQLite's `ALTER TABLE ADD COLUMN` accepts only a constant, so `strftime('now')` isn't expressible) — the migration's own `UPDATE` immediately backfills every row from `versions.created_at` → `revoked_at` → `documents.created_at`, and every INSERT binds the column explicitly, so a surviving 1970 stamp means a new write path forgot to bind it. Pre-migration *classification* changes are unrecoverable (nothing timestamped them) and deliberately not faked. Paired with the `(updated_at DESC, id DESC)` index behind `order=updated` + `updated_since=`; and `0018_published_version.sql` adds `documents.published_ver` — the **publication pointer** that decouples "what the world sees" from "what an agent last wrote" (GitHub issue #43). Single-tenant trust means any active agent key overwrites any live document, and some documents are `visibility='public'`, so before 0018 publication was a *side effect of writing*: one ordinary, fully-authorized `PUT` moved private corpus content onto a world-readable URL without ever touching the operator-only visibility flag, and no human ever decided that a particular revision should face outward. `published_ver` is that decision made a column — a PUBLIC document's HTML render path serves it, while `current_ver` keeps meaning "the newest bytes" and keeps being what every credentialed surface reads (the rule itself is the served-version convention below). Nullable, no default, **no CHECK, no FK, no index**: NULL is a real and permanent state ("nothing has ever been published"), the presence-flag posture of 0008/0015 rather than 0017's forgot-to-bind sentinel; SQLite can't express "a `versions.version_no` within THIS document" (half a composite PK) from a single-column ALTER, so existence is validated in code (`promoteVersionCore` → `version_not_found`) exactly as `documents.superseded_by` (0014) and `slug_tombstones.redirect_to` (0010) validate their pointers, and the only read is a PK-riding join. The migration backfills every live public doc to its `current_ver`, so it is invisible from outside — those URLs return the same bytes a second later. **The invariant is `visibility='public'` implies `published_ver IS NOT NULL`**, held at all four edges: `publishDocumentCore` binds it at birth when the doc is born public, `setDocumentVisibilityCore` runs `published_ver = coalesce(published_ver, current_ver)` in the *same statement* as the flip to public (so a first publication behaves exactly as it always did, while a staged choice survives), `revokeDocumentCore` nulls it alongside `current_ver`, and the migration's own UPDATE covers history. It is a version POINTER, not a fourth state axis — a *private* doc may carry one (staging a choice before the door opens) and it changes nothing until the flip, and flipping back to private deliberately leaves it alone. Status is the third state axis (revoked = existence, visibility = anonymous read, status = currency): a `deprecated` doc still serves and still ranks in search (marked in the row) but is excluded from context-pack fills by default; `archived` is unsettable until its behavior is wired. Tags join `slug`/`visibility`/`status` on the identity/classification side: they survive content updates and restores, a tag change never bumps a version, and they're no longer FTS-indexed (the `?tags=` filter is a LIKE on `documents.tags`, never FTS). R2 (`DOCS` binding) holds **two** blobs per version: the sanitized render **H** at key `<docId>/v<n>-<nonce>` and the retained source **S** at the dot-suffix sibling `<docId>/v<n>-<nonce>.src` (content-type from `source_format`). **The key is per-write-ATTEMPT, not per-`(docId, versionNo)`** — the nonce is 16 CSPRNG bytes from `newPublicId()`. Two concurrent updates both compute `nextVer = current_ver + 1` (a plain SELECT, not a conditional write); exactly one D1 batch commits on the `(document_id, version_no)` PK and the loser's rollback used to delete the *winner's* bytes, bricking a live doc into a 404 only a fresh update could heal. With a private address per attempt the loser can only delete its own. **Never re-derive an R2 key from `(docId, versionNo)`** — every reader (`serveRaw`, text/source reads, link backfill, revoke purge) reads it back from `versions.r2_key`/`source_r2_key`, which are opaque columns by design. Source bytes count toward the fleet storage cap (`size_bytes` stays "rendered H bytes"; `source_size_bytes` is the separate per-version S size — `checkStorageCap` SUMs both, coalescing NULL legacy rows to 0). `versions` rows are append-only and survive revoke as an audit trail (only the R2 bytes are purged — **both** H and the `.src` sibling). KV (`OAUTH_KV` binding) is owned by the OAuth provider library (clients, grants, tokens). **Vectorize (`VECTORIZE` binding) + Workers AI (`AI` binding)** back semantic search (docs/design/vector-search-design.md, BUILT): the `agent-web-host-docs` index (1024-dim cosine) holds **N chunk vectors per document** keyed `${documents.id}#${i}`, embedded with `@cf/qwen/qwen3-embedding-0.6b`. **No D1 migration** — vectors live entirely in Vectorize; the chunk ID yields the doc id, so there's no per-vector metadata column and no chunk-count column (the fixed `#0…#${MAX_CHUNKS-1}` range-delete handles a shrunk chunk count). The one stored metadata field, `preview`, is a non-indexed display snippet. Sync is **best-effort, eventually-consistent, OUTSIDE the D1 batch** (see the vector-sync convention below). On revoke, `documents.revoked_at` is flipped **before** the R2 batch delete so the doc is unreachable instantly even if R2 cleanup hangs; the same batch clears `documents.slug`, **retires that slug into `slug_tombstones`** (so the name is reserved forever — migration 0009, not freed), deletes the FTS row, drops the doc's outbound `document_links` rows, and stamps `updated_at`, so kill + slug-retire + search visibility all land atomically (the chunk-vector delete rides `ctx.waitUntil` after the batch — not the kill switch, just index reclaim; the read-path D1 re-join enforces `revoked_at is null` regardless). **Revoke is IDEMPOTENT on the purge path:** the R2 delete runs after the batch, is chunked under R2's 1000-key-per-call limit (2 keys per version, so a long-edited doc exceeds it alone), and lets a failure throw — so re-issuing the revoke is the recovery. A second `DELETE` on an already-revoked doc therefore returns `200` and RE-RUNS the purge while skipping the D1 batch entirely (no re-stamped `revoked_at`, no fictitious `updated_at`); only an unknown/malformed `public_id` 404s. Don't "fix" that back to a 404 — it would tell the operator a retry was pointless while unsanitized `.src` bytes stayed resident forever.

**Single-tenant trust model.** Any active agent key under one operator can `PUT` to any document — `core.ts` deliberately does not scope updates by `created_by`. **The write cores take an `Author` (`{kind:"operator"} | {kind:"agent";agentId}` — the `Principal` union from `access.ts`, minus anonymous), NOT a bare `agentId: string`** (migration 0013): the operator is a first-class author recorded as the operator principal, never smuggled through as a fake agent (the old `restoreVersionCore("operator")` string hack is gone). `documents.created_by`/`created_by_kind` retain the original creator (`created_by` is NULL for an operator-created doc — its `created_by_kind` is `"operator"`); each new version records its own writer in `versions.author_kind`/`author_agent_id` (queryable, not just R2 `customMetadata`). The operator authors through `POST /admin/documents` / `PUT /admin/documents/:id` (operator JSON write door, `admin.ts`), same core path as the agent door. `listDocumentsCore` shows the whole fleet to every caller. If per-agent scoping ever becomes needed, add a `createdBy?` arg to core functions. **Agents can also CURATE, not just author** — `PUT /d/:id/tags` and `PUT /d/:id/status` (`curateDocumentTags` / `curateDocumentStatus` in `admin.ts`, `requireReader`-gated) put the two no-version-bump classification mutators on the agent door, **and the MCP tools `set_document_tags` / `set_document_status` put them on the connector door too** (same cores, same reasoning — the MCP gap `docs/design/context-packs-design.md` had filed as "still deferred over MCP" is closed). That is not a widening: an agent key already replaces any document's entire *content*, so re-tagging or deprecating it grants strictly less. **`visibility`, revoke and PROMOTION stay `requireOperator`, deliberately** — visibility is the boundary between "private to the fleet" and "readable by the anonymous internet" (a different KIND of authority from anything exercised inside the fleet), revoke is irreversible, and promotion (`POST /admin/documents/:id/promote`, migration 0018) is the verb that moves bytes ACROSS that boundary: it is the whole reason `published_ver` exists, since an agent that could promote its own write would have re-created the exfiltration path the column closes. **There is no agent-reachable promote and none may be added** — not an HTTP twin on the `/d/` door, not an MCP tool, not a `published_ver` input on an existing write tool — for the same reason no MCP tool takes `visibility` as an input (see the visibility paragraph below, which pins that rule in the same terms). Agents SEE the pointer (every MCP write/read envelope echoes `published_version`) so they can report "stored but not live yet"; they never move it. A new classification surface belongs on the agent side only after asking which side of THAT line it falls on: tags and status stay agent-reachable precisely because neither reaches an anonymous surface, while promotion is defined by reaching one. **Unsanitized source bytes are now also at rest in R2** (the `.src` blob per version, since migration 0008): it is auth-gated (credential-gated — operator or agent, never anonymous) and **never served to a browser** — the render path is still H-only behind the iframe+CSP wall. Source retention changes only the *ingestion-as-context* surface (an agent asking for `representation:"source"` can pull markup-form bytes the sanitizer would have neutralized on the render path); the provenance tag + credential auth cover exactly that increment, and revoke purges the `.src` siblings alongside H so the kill switch leaves no unsanitized source resident.

**Per-document visibility — a two-axis read model (migration 0011, GitHub issue #7).** Orthogonal to revoke: every document is `public` or `private`, and `src/access.ts` is the single pure chokepoint. `canRead(principal, doc)` is top-down first-match-wins (revoked→false, operator→true, agent→true, anonymous→`visibility === "public"`); `resolvePrincipal` resolves operator → agent → anonymous from the request. **Visibility gates ONLY the anonymous browser surface** — `serveShell` / `serveRaw` / `serveBySlug` / `serveHomepage`, all enforced at the **`serveRaw` chokepoint** (`resolvePrincipal` → `canRead`). The operator (cookie session OR bearer) and any active agent key read everything, so the credentialed read surfaces (`/text`, `/source` — gated operator-or-agent via the `requireReader` helper, operator ≥ agent; MCP read/list/search — agent-scoped) are unaffected by visibility, and `listDocumentsCore` still shows the whole fleet to every authenticated caller. A private doc denies as the **same opaque 404** a missing/revoked doc gives — **never a 401, no existence oracle**. New docs are born at `DEFAULT_DOCUMENT_VISIBILITY` ([var] in `env.ts`/`wrangler.toml`, default `"private"`), bound EXPLICITLY by the write path so the column's own `DEFAULT 'public'` only ever covers legacy rows; the operator flips it via `POST /admin/documents/:id/visibility` (JSON) or the Manage page (`setDocumentVisibilityCore`, no version bump). Visibility-CHANGE authority is a separate operator check (`requireOperator`), deliberately kept OUT of `canRead` (which governs read on the public surface and nothing else) — and it stayed operator-only when `tags`/`status` became agent-reachable (see the trust-model paragraph). Because an agent can neither set nor undo it, **every MCP write and read envelope echoes `visibility`** so an agent knows before it hands a human a URL that 404s for them (`mcpVisibilityEcho` in `contract.ts`; `currentEcho` in `mcp.ts` re-reads the row — the same single row read now also carries the migration-0018 `published_version`). No MCP tool takes `visibility` as an INPUT and none should be added — the identical rule now covers `published_ver` (see the trust-model paragraph above).

**Sanitizer is bundled as WASM.** `src/sanitizer.ts` imports `sanitizer/pkg/sanitizer_bg.wasm` directly as a `WebAssembly.Module` (wrangler's `[[rules]] type = "CompiledWasm"` rule) and calls `initSync`. **Do not use the wasm-pack `--target web` glue's `init()`** — it tries to fetch via `import.meta.url`, which doesn't exist on Workers. Init is lazy and idempotent. (`skills/publishing.md` is **no longer bundled** — it used to be a `[[rules]] type = "Text"` import served as the `awh://publishing-guide` MCP resource, but MCP resources aren't surfaced to most connector models (Claude web/mobile, ChatGPT), so the guide is now an on-platform **document**, slug `slopcafe-publishing-guide`, mirrored via `scripts/doc-web.mjs` — GitHub issue #38. A `[[rules]] type = "Text"` rule is BACK in `wrangler.toml`/`.example` since MCP Apps, but for `**/*.html` only: it bundles `src/mcp-app-template.html` as the `ui://` viewer template — a HOST-fetched artifact, not a model-surfaced guide, so issue #38's rationale is untouched and the guide itself stays an on-platform document, un-bundled.)

**MCP server lifecycle.** `src/mcp.ts` builds a fresh `McpServer` (**SDK v2**, `@modelcontextprotocol/server` — the 2026-07-28 line; the old `@modelcontextprotocol/sdk` stays in the tree only as the `agents` package's exact v1 peer, never import it) **per request**, handed to the stateless `createMcpHandler` from **`agents/mcp/server`** as a **factory** — stateless per MCP **2026-07-28** (`server/discover` + automatic legacy `initialize` fallback: ONE factory serves both protocol eras, so 2025-era connectors keep working through the SDK's compatibility lane with no client action). The per-request rule survives the upgrade with a new rationale: it used to be "SDK ≥1.26 throws on reuse"; now the v2 factory model *formalizes* it (instances are still single-connect, and cross-request state would still leak). The agents 0.20 wrapper also validates Origin/Host: server-side connectors (Claude web/ChatGPT/Claude Code) send no Origin header and pass untouched; `allowedOriginHostnames` exists if a browser-origin MCP client ever appears — documented, deliberately not configured. **SEP-2549 cache hints (GitHub issue #45):** the `McpServer` constructor declares `cacheHints` for `tools/list` + `server/discover` via `STATIC_SURFACE_CACHE_HINT` (1 h, `public` — the tool list is static per deploy and identical for every principal; rationale on the constant). 2026-era responses only — the 2025 codec has no cache path, so legacy bytes are unchanged; since MCP Apps, `resources/list` (a third constructor `cacheHints` entry) and the ui:// template's `resources/read` (a per-registration `cacheHint`) carry the same hint, while `prompts/list` stays N/A (no prompts registered). The eleven tools (`publish_document`, `update_document`, `edit_document`, `set_document_tags`, `set_document_status`, `read_document`, `view_document`, `list_documents`, `search_documents`, `load_context_pack`, `create_publish_credential`) close over `props.agentId` resolved upstream — they never re-validate auth. (`create_publish_credential` is the lone non-document tool: it mints a short-lived `awh_` key for the byte-exact curl publish path via `mintEphemeralKey` — see the convention bullet below.) **`view_document` is the MCP Apps (SEP-1865, extension id `io.modelcontextprotocol/ui`) presentation read** — SHOW a document to the human, vs `read_document`'s ingest-as-context: `public_id` XOR `slug` (+ optional `version`), returning one flat envelope (resolved id, `/d/<id>` url, metadata echoes incl. `visibility`/`published_version`, and the FULL sanitized H as `content`, `format:"html"`; a retired-but-redirecting slug is a `slug_retired` error naming the target, never a second envelope shape). Its tool `_meta` links it — in BOTH spellings, nested `ui.resourceUri` and the deprecated flat `"ui/resourceUri"`, since each host generation reads only its own — to the `ui://slopcafe/document-view.html` template resource (`src/mcp-app-template.html`, mime `text/html;profile=mcp-app`), which an Apps-capable host (Claude web/desktop, ChatGPT) fetches via ordinary `resources/read` and renders in ITS sandboxed iframe under ITS deny-all CSP; the server capabilities advertise `resources: {}` + `extensions: { "io.modelcontextprotocol/ui": {} }`. Registration is UNCONDITIONAL on every per-request instance (an Apps host may prefetch the template before any tool call), and a host that doesn't know the extension simply ignores the `_meta` + ui:// resource and renders the ordinary structured JSON result — graceful degradation everywhere else (Claude Code is not an Apps host; Claude mobile unconfirmed). See docs/design/mcp-apps-design.md. **`set_document_tags` and `set_document_status` are the two CLASSIFICATION writes** — full-replace a doc's tags (send `[]` to clear; tags are silently *sanitized* rather than rejected, so the response echoes what was STORED and the caller diffs), or set lifecycle `active`/`deprecated` with an optional `superseded_by` (a `public_id` **only**, never a slug; must be live, may not be self; setting `active` clears it). Neither changes a byte or bumps a version, so both echo `visibility` but deliberately **not** `published_version` — nothing moved, so there is no "stored but not live yet" gap for a promote to close, and echoing the pointer would imply a relationship that doesn't exist. They are agent-reachable for the one reason that governs this entire axis: **neither field reaches an anonymous surface** (tags are a fleet-internal filter; status marks currency and gates only pack fills), and an agent key that already replaces a document's whole *content* grants strictly more. `visibility`, revoke and promotion sit on the far side of that line and stay operator-only — **no tool takes them as an input and none may be added by analogy from these two** (see the trust-model paragraph). Two tools rather than one `curate_document`, deliberately: independent columns, separate cores, separate error unions, no atomic path for a combined call (tags applied, status rejected on a bad `superseded_by`, both hidden behind one `isError`), and an "at least one of" input schema JSON Schema can't express. Their HTTP twins are `PUT /d/:id/tags` and `PUT /d/:id/status`. **HTML vs Markdown is a `format` parameter, not separate tools** — an earlier revision had `publish_document`/`publish_document_markdown`, `update_document`/`update_document_markdown`, and `read_document`/`read_document_text` twins; a `format` enum collapsed those six into three (`publish_document`, `update_document`, `read_document`). On the two write tools `format` (`"html"` | `"markdown"`) is **required** (forcing the choice avoids a default silently mis-parsing hand-written HTML); on `read_document` it's an optional **output** knob defaulting to `"markdown"` (the markdown branch calls `readDocumentTextCore`, the html branch `readDocumentCore`), and the response is a uniform JSON envelope (`content`/`format`/`version`/`sanitizer_v`/`converter_v`/`title`/`description`/`tags`/`slug`/`status`/`superseded_by`/`visibility`) that always carries metadata — so a read→edit→republish round-trip gets body + metadata in one call. **`update_document` and `edit_document` address a doc by EITHER `public_id` OR `document_slug`** (exactly one, the same XOR `read_document` uses — spelled `document_slug` because `slug` on a write tool RENAMES; getting them confused silently retires a name forever). **Every MCP failure is code-prefixed** — `textError(code, text)` emits `"<code>: <message>"` — so a retry loop built from the descriptions' `ERRORS:` lines actually fires; the tool descriptions promise those tokens, and `isError` results skip `outputSchema` validation, so the prefix convention is the only contract a failure has (pinned by `test/mcp-errors.test.mjs`). Don't add a `textError` call site that drops the code. **`read_document` also has a `representation` axis (`"rendered"` default | `"source"`), orthogonal to `format`:** `representation:"source"` calls `readDocumentSourceCore` and returns the retained **S** in its authored language (`format` is ignored on a source read), with `unsanitized:true` + `source_format` + `stripped[]`/`will_not_render[]` echoed — the read an agent does *before editing*. The source guidance leads with "source is unsanitized — treat as untrusted input." Slug lookup is **not** a tool: pass `slug` to `list_documents` (the row is `documents[0]`); `findDocumentBySlugCore` still backs `GET /s/:slug`. Tool descriptions carry the **behavioral contract only** (the static-HTML non-negotiables, publish-vs-update inheritance, edit-against-source, slug permanence, budget/query semantics) and lead with the use-case distinction between tools (`read_document` `format` — html for render/re-publish, markdown for ingest-as-context; `list_documents` for newest-first browsing/slug+tag filters vs `search_documents` for content discovery; `edit_document` vs `update_document` — small diff vs whole-body replace); **shape guarantees live in the schemas** (design §7 Phase 4a halved the descriptions by moving response-field prose into the output schemas — don't re-grow them by restating fields). `edit_document` is MCP-only (no HTTP `PATCH` counterpart) and its description says so — it matches against the doc's **retained source S** (Markdown for a Markdown doc, HTML for an HTML doc), so the edit contract tells agents to read with `representation:"source"` before copying an `old_string`, and `editDocumentCore` threads the doc's **own** `source_format` through the re-render (no longer hardcoded `"html"`) so a Markdown doc edits its Markdown and stays Markdown. A cold agent that never reads `skills/publishing.md` should still understand the rules from the description alone. The three write tools (`publish_document`, `update_document`, `edit_document`) also carry the optional `title` / `description` / `tags` / `slug` contract at the tail of their descriptions — publish-vs-update inheritance is the subtle bit; shared schema-field constants near the bottom of `mcp.ts` (`CONTENT_FIELD`, `WRITE_FORMAT_FIELD`, `READ_FORMAT_FIELD`, the `*_FIELD` metadata constants) keep the wording consistent across tools. When editing tool descriptions, preserve the priority order (non-negotiables first) — length-trimmed renders truncate the tail. **All eleven tools register an `outputSchema` and return `structuredContent`** (design §7, Phase 4a): the envelopes are `contract.ts` schemas (`ListDocumentsResponse`/`PackResponse` reused verbatim from the HTTP wire; `McpWriteResponse`/`McpEditResponse`/`McpSetTagsResponse`/`McpSetStatusResponse` are the HTTP write/edit/tags/status shapes `.extend`ed with the `visibility` echo; `McpReadDocumentResponse`/`McpViewDocumentResponse`/`McpSearchDocumentsResponse`/`CreatePublishCredentialResponse` are MCP-only), the SDK **hard-fails any non-error result that doesn't validate** (envelope drift = a broken tool call, not silent drift), and every success path goes through the `structuredOk` helper (the same JSON also rides the legacy text block; `textError` results are exempt from validation). Two union-shaped outputs are encoded as optionality because a tool output schema must be ONE object: `read_document` (document envelope ∪ unfollowed-redirect report) and `search_documents` (`pack`/`omitted` present only with `include_bodies`).

## Conventions and gotchas

- **`If-Match` is required on `PUT /d/:id`** (428 if missing). Send `"v<n>"` for optimistic concurrency or `*` to skip. Strong tags only; no weak tags, no multi-tag lists.
- **`POST /d` / `PUT /d/:id` accept `Content-Type: text/html` or `text/markdown`** (`text/x-markdown` too; anything else → 415; the gate is `parseInputFormat` in `src/index.ts`). A Markdown body is parsed (CommonMark + GFM) to HTML before sanitizing; either way the stored bytes are sanitized `text/html; charset=utf-8`, and which input path produced the version is recorded in `versions.source_format`.
- **Optional `X-Content-SHA256` byte-exact integrity check on `POST /d` / `PUT /d/:id`** (`src/integrity.ts`, wired via `readVerifiedBody` in `src/index.ts`). Hashes the **raw received body before sanitization** — verifies the wire, not the sanitizer's transformation, so it's orthogonal to the `modified` flag. Malformed header → 400 `bad_integrity_header`; mismatch → 422 `integrity_mismatch`. **HTTP-only by design** (the companion to the `curl --data-binary @file` byte-exact publish path): the hash must come from the same deterministic tool that streams the file, so there is no MCP equivalent — the two primary MCP write-tool descriptions say so. `docs/design/byte-exact-publish-design.md` records the rationale (the binding constraint at 66–85 KB is model regeneration of the `content` argument, not transport; chunked-append doesn't fix it).
- **Short-lived publish credentials (`agent_keys.expires_at`, migration 0007).** The byte-exact curl path needs a bearer at the shell, but Claude's connector settings can't store one and the connector's OAuth access token isn't exposed to the model/shell. So the already-OAuth-authenticated MCP session mints one on demand: the `create_publish_credential` tool → `mintEphemeralKey` (`src/admin.ts`) inserts a normal `awh_` key with a non-NULL `expires_at` (default 15 min, max 60, clamped). `authenticateAgent` (`src/auth.ts`) rejects expired keys exactly like revoked ones via the pure `isKeyExpired` helper. `expires_at = NULL` = never expires (every operator-minted key + legacy rows), so the migration is a no-op for them. **No scope column in v1** — single-tenant, the damaging vector (overwriting docs) isn't blocked by a write-only scope anyway, and the minted key grants nothing beyond the MCP session's existing authority; scope-limiting is the additive multi-tenant follow-up. The minted **`key`** is the deliberate disclosure surface — never log it (same discipline as the OAuth token). **The returned `recipe` is NOT a secret** (GitHub issue #34): it references the key via an `$AWH_KEY` env var (the agent `export`s the `key` once — prefix the line with a space to skip shell history) instead of inlining it, so the token never reaches the curl command line and the recipe is safe to echo. Don't "re-harden" by interpolating `result.key` back into the recipe — that's the leak #34 removed. Revoke early via `DELETE /admin/keys/:id`.
- **Optional metadata on POST/PUT /d**: `X-Doc-Title`, `X-Doc-Description`, `X-Doc-Tags` (comma-separated), `X-Doc-Slug`. MCP write tools take the same shape as schema fields. **Header values are read as UTF-8** (`decodeHeaderUtf8` in `metadata.ts`, issue #31) — an HTTP header value arrives as a Latin-1 byte view (Fetch ByteString: one JS char per raw byte), so without the decode a non-ASCII title (`Café — résumé`, an em-dash, CJK) would store as mojibake. The decode is *fatal-with-fallback*: pure ASCII is identity, valid multi-byte UTF-8 is recovered, and a lone Latin-1 byte (e.g. a browser `fetch` sending `é` as `0xE9`) is invalid UTF-8 so it's preserved as-is. This makes the header channel UTF-8 like the body and MCP JSON args, and like the served `charset=utf-8` render path — so agents send non-ASCII literally instead of entity-encoding (the sanitizer normalizes character entities to literal UTF-8 anyway; only `& < > "` + `&nbsp;` stay encoded). On UPDATE, an *omitted* field inherits the prior version's value (or, for slug, the current document's value); an explicit `""` clears (and for title, re-derives from the new content's H1; for slug, releases it). Tags charset is restricted to `[A-Za-z0-9_-]` — invalid chars are silently stripped, not rejected. Slug charset is `/^[a-z0-9](?:[a-z0-9_-]{0,62}[a-z0-9])?$/` — invalid input is **rejected** (`invalid_slug` → 422), not silently sanitized (uniqueness means mutating the input could surprise-collide). Slug is unique across live docs (partial UNIQUE INDEX), conflict → `slug_taken` → 409. The render path applies anti-phishing normalization to title only (bidi/zero-width strip); description stores bidi for fidelity since it doesn't reach the browser tab.
- **Slug AND tags live on `documents`, not `versions`.** Title/description evolve per-version because they describe content; **slug and tags are document-level** (tags since migration 0012) — slug is identity-adjacent (uniqueness per-document), tags are classification (a document's place in the collection, not a revision's wording). Both survive content updates and restores and never bump a version when changed. It survives version increments unchanged unless the agent explicitly changes it (atomic claim-new + retire-old in the same D1 batch). On revoke (and on rename/clear) `documents.slug` is set NULL alongside `revoked_at`, but the slug is **NOT reusable** — it is retired into `slug_tombstones` (migration 0009) and reserved forever; `/s/<slug>` then returns **410 Gone** and a reclaim attempt → `slug_retired`. `documents.slug` therefore always means "the live slug"; the permanent reservation is the separate tombstone table (a claim checks both via `resolveSlug`; `serveBySlug`/`read_document` consult `findSlugTombstoneCore` on a live-lookup miss to choose 410-vs-404). This reverses the original "released on revoke" contract per GitHub issue #6 — slug reuse is surprising (a shared/linked `/s/<slug>` must not silently start serving unrelated content). Pulling slug from `d.slug` in the joined read/list queries — not from prior_metadata — keeps the per-version `resolveMetadata` helper unaware of cross-document state. **A retired slug can REDIRECT (migration 0010, `slug_tombstones.redirect_to` = target `public_id`), but only LOUDLY:** a rename auto-forwards the old slug to the same doc's `public_id`; the operator can cross-redirect via `POST /admin/slugs/:slug/redirect`; `serveBySlug`/`read_document` never auto-follow — browser gets a click-through interstitial, agent gets `409 slug_redirected` (HTTP) / a `{redirected:true}` envelope (MCP) and must opt in with `follow_redirects`. Single-hop (target is a `public_id`, so no chains/loops; a dead target falls back to 410). **The redirect target is additionally gated on `canRead`** (`redirectTargetReadableBy` in `serve.ts`): to an anonymous caller a target it couldn't read directly is indistinguishable from a dangling one — plain 410, never named — so the interstitial can't become a private-doc oracle. `resolveRedirectTarget` in `core.ts` filters `revoked_at is null` but deliberately NOT `visibility` (visibility isn't part of the wire `RedirectTarget` shape), so **every caller must gate the result itself**. Operator escape hatch `DELETE /admin/slugs/:slug` force-releases a tombstone (the only un-retire path); `DELETE /admin/slugs/:slug/redirect` drops just the redirect. **An AGENT may not change the slug of a PUBLIC document — `slug_locked` (403), migration 0018/issue #43.** A slug is a ~60-char operator-chosen string sitting at an anonymous-readable address, so an agent renaming a public doc was a small but real write channel onto the open web — the same class of hole `published_ver` closes for the body, and one the version pointer can't cover (a rename takes effect immediately, no promote involved). Enforced once, in `updateDocumentCore`, keyed on the resolved slug *action* rather than the field's presence: re-sending the doc's existing slug is still a clean no-op, while a rename **and a clear** are both locked (`invalid_slug`/`slug_taken`/`slug_retired` can fire ahead of it, since `resolveSlug` runs first). Because `editDocumentCore` and `restoreVersionCore` delegate there, one check covers `PUT /d/:id`, MCP `update_document` and `edit_document`, and restore-with-slug; publish is out of scope (a brand-new doc nobody has linked yet) and operator slug changes are untouched. Content writes are NOT affected — the lock is on the slug field alone, and the remedy in both error messages is "re-send the update without a slug field, or ask the operator to rename it." **`tags` and `status` were checked against this same line and deliberately NOT restricted**: neither reaches an anonymous surface (tags are a fleet-internal filter, status marks currency and gates only pack fills), so they stay agent-reachable per the trust-model paragraph.
- **Operator document-management page + browser login-link 404 (`src/serve.ts`).** `GET /d/:id/manage` (`serveManagePage`) is the cookie-session-gated operator page folding five actions onto one doc: visibility toggle (`handleVisibilityForm`, `POST /d/:id/visibility`), slug add/rename/clear (`handleSlugForm`, `POST /d/:id/slug`), tags (`handleTagsForm`), lifecycle status (`handleStatusForm`), and revoke — plus the read-only Version history and Link graph panels. A logged-out caller gets a sign-in card rendered with **no DB hit** (so the page is no existence oracle). The shared `authorizeOperatorForm` handles the auth ladder. **`GET /d/:id/revoke` (`serveRevokeConfirm`) resolves operator auth BEFORE any DB read**, same discipline: it used to query D1 up front and branch 200-vs-404 on existence, which made it an existence oracle for exactly the private documents `/d/:id` hides. A caller carrying an `Authorization` header gets the opaque `notFound()`; a plain browser gets the paste-the-token confirm card, rendered with **no query**, so the bytes are identical for a live, private, revoked, or never-existent id (a wrong id fails at POST time). The shell topbar's old "Revoke…" kebab item is now **"Manage…"** (revoke folded into the manage page); a signed-in topbar also shows a Public/Private badge. JSON operator twins live in `admin.ts`: `setDocumentVisibility` (`POST /admin/documents/:id/visibility`) and `setDocumentSlug` (`POST /admin/documents/:id/slug`); the slug path reuses `setDocumentSlugCore` (no version bump; `resolveSlug` + `tombstoneSlug` so a rename auto-forwards — identical to the agentic `update_document` slug change). **Browser login-link 404:** because private docs exist, a valid `/d/:id` or `/s/:slug` URL 404s to a logged-out operator — so `notFoundBrowser` (+ `NOTFOUND_CSP`) returns an HTML 404 card with a "Sign in" link that round-trips back via `/login?next=<requested URL>`. It **never reads doc state** (only echoes the requested path into `next`), so a private doc's 404 is byte-identical to a nonexistent one's for the same URL. Wired into `serveShell` (all three 404s), `serveBySlug` (private-to-anon; malformed + never-claimed-slug pick HTML-vs-plain by the `Authorization` header), and `serveRetiredSlug`'s no-tombstone case. The **byte/HTML** surfaces (`/raw`, `/v/:n/raw`, the shells, the `/manage` + `/revoke` POST handlers) keep the plain `text/plain` `notFound()`; the **machine-readable** routes (`/text`, `/source`, `/links`) answer `notFoundJson()` instead — see the JSON-404 convention below.
- **Operator version history + restore-as-new-version (`src/serve.ts`, `src/core.ts`, MCP).** No migration — `versions` already retains every version's H (and `.src`) bytes until revoke purges them, so "history" is pure additive read code. Operator browser surface: `GET /d/:id/v/:n` (shell) + `/d/:id/v/:n/raw` (bytes), `authenticateOperatorRequest`-gated (Bearer OR cookie), and a Version history table on the manage page with a Restore button per non-current version (`POST /d/:id/restore`). **Both now have JSON twins** so a scripted operator client (the Flutter app, a rollback script) doesn't have to scrape HTML for a first-class operator feature: `GET /admin/documents/:id/versions` (→ `ListVersionsResponse`) and `POST /admin/documents/:id/restore` `{version:n}` (→ the ordinary write envelope + `restored_from`), both `requireOperator`, both in `admin.ts` over the same `listVersionsCore`/`restoreVersionCore`. Callers must check each row's `source_present` before offering Restore. This is an **operator** axis, deliberately NOT folded into `canRead`/visibility — a public doc's history is as operator-only as a private one's; a non-operator gets the same opaque 404. Agents read history through MCP `read_document` (`version` to read one, `include_history` for the manifest) — **read-only; there is no agent restore in v1.** **Restore is mandatorily restore-as-NEW-version, never a `current_ver` rewind:** `updateDocumentCore` computes `nextVer = current_ver + 1`, so pointing `current_ver` backward would make the next ordinary update collide on the `(document_id, version_no)` PK. `restoreVersionCore` reads version N's retained source S and re-publishes it forward through `updateDocumentCore`, restoring body + title/description/tags but keeping the doc's current slug (slug is identity, not content). A pre-0008 version with no retained source **hard-fails `source_unavailable`** — there is deliberately NO fall-back-to-H legacy branch (identical to `edit_document`'s contract); the manage table shows a muted "no source" in place of the Restore button, and such docs are revoke-and-republished (the pre-launch no-legacy-code stance). The `test/`-style suite has no D1 harness, so this path is covered by typecheck + the local `wrangler dev` E2E (publish → update×2 → restore v1 → confirm the next update lands monotonically, no collision).
- **The served-version rule is a security boundary, and `src/served-version.ts` is its ONE copy (migration 0018, GitHub issue #43).** The rule: `served = (visibility === 'public' && published_ver !== null) ? published_ver : current_ver` — i.e. a PUBLIC doc renders `published_ver ?? current_ver`, a PRIVATE doc always renders `current_ver`. Note what it does NOT contain: **a principal term.** A public document serves its promoted version to the anonymous visitor, the agent and the operator alike, deliberately — a rule that showed the operator the newest bytes at the same URL would make the one person who can promote the one person who can't see what everyone else is looking at, which is backwards for a review gate (the operator reads staged work at its own explicit address, `/d/:id/v/:n`, unchanged by 0018). Private renders current because private is *already* the gate: nobody anonymous can read it, so staging would only force an operator round-trip into the fleet's own write→look→write loop. **It applies to the HTML byte path ONLY** — `GET /d/:id`, `/d/:id/raw`, `/s/:slug` and `/` (their ETag now keys on the SERVED version, and the shell's title/description/version plus the retired-slug interstitial's title come from it). **Everything credentialed or machine-readable stays on `current_ver`, and that is not an oversight to "align"**: `/text`, `/source`, `/links`, every MCP read, list, search, packs, FTS, vectors, the link graph, and the operator's explicit `/v/:n` reads. Those callers hold a key that already reads the whole corpus, so a stale render would protect nothing while making `edit_document` patch bytes it cannot see — the gate is about what LEAVES the fleet, not what the fleet may read. `served-version.ts` is a **leaf module** (no runtime imports; the `Visibility` import is `import type`, so it erases) because both `serve.ts` and `core.ts` need the rule and `serve.ts` already imports `core.ts` — the reverse edge is a module cycle, so the only alternatives were a leaf or a second copy, and a drifted copy of *this* rule is a silent anonymous-disclosure hole. Two exports: `SERVED_VER_SQL` (the SQL fragment for callers issuing their own join — **alias the documents table as `d`**; interpolated rather than bound because it names columns and contains no caller input) and `servedVersion(doc)` (the same rule for callers already holding a row). **Adding a render site means routing it through one of those two.** A site left on `current_ver` is not a cosmetic inconsistency — it is a hole: it re-opens exactly the path 0018 closed, publishing an agent's newest bytes to the anonymous internet with no operator in the loop. Callers must still gate on `revoked_at is null` first (revoke nulls both pointers, but a query without that guard can join a stale pointer against purged R2 keys). Related: `/d/:id/raw` now emits **`x-doc-current-version`** (the newest version number) for non-anonymous principals only — absent for anonymous, so it never discloses that staged work exists — because `/raw`'s ETag reports the SERVED version and is therefore no longer a valid `--if-match` preflight; a writer preflighting an update must prefer that header and fall back to the ETag only when it's absent.
- **The machine-readable read routes answer JSON, not `text/plain` — and their 404 may carry a shape hint.** `/d/:id/text`, `/d/:id/source` and `/d/:id/links` return `notFoundJson()` (`{error:"not_found", message}`, `application/json`) rather than `notFound()`'s `Not Found\n`. Those handlers already emitted JSON for 401 (`unauthorizedJson`) and for `/source`'s 409 `source_unavailable`, so a plain-text body made the *most common* failure the one case a JSON client couldn't parse — and `docs/http-api.md` had documented these as a `not_found` code all along. **Opacity is unchanged**: missing, revoked, private, and malformed-id all answer identically for the same URL. The only variance is `message`, produced by the exported **`idShapeHint(id, slugRoute)`** — purely syntactic, derived from the caller's own path segment with **no DB read**, so it can never become an existence oracle. When the segment fails `PUBLIC_ID_RE` but validates as a slug it names the conversion (`GET /d?slug=…`, plus `/s/:slug/text` where a slug-addressed twin exists — `/source` and `/links` have none). A well-formed `public_id` falls through to the bare message: the `PUBLIC_ID_RE` guard is load-bearing because a lowercase id also satisfies the slug charset, and telling its owner "that isn't a public_id" would be actively wrong. Reused by `PUT /d/:id` (`index.ts`) and every `/admin/documents/:id/*` mutator (`documentNotFound` in `admin.ts`). We deliberately do NOT auto-resolve a slug in the id slot — the two address different things, and blurring that is how a shared `/s/<slug>` ends up treated as an unguessable capability URL.
- **`version_not_found` is a first-class `ErrorCode`, and it may only ever be emitted behind an operator gate.** The two routes that address a document *and* a version inside it — `POST /admin/documents/:id/restore` and `POST /admin/documents/:id/promote` — used to report "that version doesn't exist" as `404 not_found` carrying an optional `version` field, which made the discriminator between two misses with **different remedies** (give up vs. pick another version) a field's *presence* — precisely what a client switching on `error` cannot see. It also forced `ErrorBody`'s `not_found` member to declare an optional `version` no other emitter ever set. The split (2.0 ledger entry 7) gives the version miss its own code with `version` REQUIRED, since it can't be emitted without one; `not_found` is context-free again like every other plain miss. **The status class is unchanged (404) — the break is the discriminant**, so a consumer switching on `error` adds one arm and one reading `not_found.version` moves to `version_not_found.version`. **The hard rule: never emit this code on an anonymous-reachable surface.** It is safe on those two routes *only* because `requireOperator` has already run — the operator can enumerate every version at `GET /admin/documents/:id/versions`, so telling the two misses apart discloses nothing it can't already read — and this is the operator door catching up to the agent door, since MCP `read_document`'s `version` arg has surfaced the identical token through `textError` since version-pinned reads shipped. Anywhere anonymous, "the document is live but that version isn't" separates a real document from a missing one, which is the existence oracle every opaque 404 in `serve.ts` exists to prevent. Related: the same change *declared* `source_unavailable`'s optional `version` context (restore had emitted it undeclared since before `contract.ts` existed — a latent spec violation, since every `ErrorBody` member is `additionalProperties: false` in `openapi.json`, so an undeclared field makes a strict codegen'd consumer reject a response the server considers correct).
- **`GET /d/:id/text` and `/s/:slug/text` content-negotiate on `Accept`.** `application/json` returns the `ReadTextResponse` envelope (body **plus** title/description/tags/slug/status/superseded_by — data `readDocumentTextCore` already returned and the route used to discard); anything else, including a wildcard `Accept` and no header at all, keeps the historical `text/markdown` body. `Vary: Accept` rides both branches. The envelope exists because a metadata-less body pushed a caller that wanted "body + is it deprecated?" toward either two round trips or the shortcut to `/source` — which hands back UNSANITIZED bytes to ingest as context. Content negotiation, not a `/text.json` route: `/d/:id` and `/s/:slug` already negotiate (on `Authorization`) and the shape already existed in `contract.ts`.
- **Every JSON error carries `Link: </openapi.json>; rel="service-desc"`, and `/healthz` is the in-band API map.** An agent handed only a base URL and a key had no path to the routes: the root is HTML, the catch-all 404 said "no such route", and the 401s said "valid agent key required" — all dead ends. Now the three JSON-error helpers (`jsonError` in `index.ts`, `jsonError`/`documentNotFound` in `admin.ts`, `operatorError` in `session.ts`, plus `unauthorizedJson`/`notFoundJson` in `serve.ts`) attach the RFC 8631 `service-desc` relation, the credentialed 401s and the catch-all 404 append `API_DISCOVERY_HINT`, and `/healthz` carries absolute `openapi` / `docs` / `mcp` pointers built from the **request** origin (so dev/staging self-describe). `SERVICE_DESC_LINK` lives in `serve.ts` and is imported by `index.ts`/`admin.ts`; `session.ts` keeps its own copy because `serve.ts` imports it and the reverse edge would be a module cycle — if a fourth copy appears, promote it to a leaf module.
- **Agent-reachable classification writes are `PUT`, not `POST`.** `PUT /d/:id/tags` and `PUT /d/:id/status` (`curateDocumentTags`/`curateDocumentStatus`, `requireReader`) are the agent-door twins of the operator's `POST /admin/documents/:id/{tags,status}`. `PUT` because `POST` on those two paths is already taken by the manage page's HTML forms (`handleTagsForm`/`handleStatusForm`, operator-only) — and because both are full replacements of a subresource, not appends. Bodies, cores and responses are identical to the operator twins; only the door differs. **The MCP tools `set_document_tags` / `set_document_status` are the third door onto the same two cores** — they address the doc by `public_id` XOR `document_slug` rather than a path id, and add the `visibility` echo every MCP envelope carries, but the authority and the semantics are identical. Three doors, two cores, one line: see the trust-model paragraph for why these two and not `visibility`.
- **`public_id` regex is fixed**: `/^[A-Za-z0-9_-]{22}$/` (`PUBLIC_ID_RE` in `src/serve.ts`). It's safe to interpolate into HTML templates after this check; `serveShell` does so.
- **Storage cap is best-effort, but it FAILS CLOSED on a bad `[var]`.** `checkStorageCap` runs `SUM(size_bytes)` outside the insert batch; two concurrent writes can both pass. v1 accepts the slight overrun. **`storageCapBytes(env)` in `core.ts` is the SINGLE reader of `STORAGE_CAP_BYTES`** — used by the cap check, the console dashboard, and `/healthz`, so the three can never disagree. The `[var]` is typed `string` on `Env`, which is a compile-time shape guarantee and nothing more: a forker can still land `"2 GiB"` or delete the line. The old inline `Number(env.STORAGE_CAP_BYTES)` turned that into `NaN`, and every comparison against `NaN` is false — a typo silently DISABLED the guardrail with no log line. Now a non-finite or ≤0 value logs and falls back to `DEFAULT_STORAGE_CAP_BYTES` (2 GiB, the same value `wrangler.toml.example` ships). Don't re-introduce a raw `Number(env.…)` read anywhere.
- **List endpoints are cursor-paginated** (`src/pagination.ts`). The list surfaces — `GET /d` (agent-reachable, `requireReader`), `GET /admin/agents`, `GET /admin/agents/:id/keys`, `GET /admin/documents` (operator), and the MCP `list_documents` tool — share `parseHttpListParams` / `parseMcpListArgs` + the `paginate()` peek helper. Default page size 50, max 200. Ordering is `(<time column> DESC, id DESC)` — the `id` tiebreaker is mandatory because D1's strftime stamps to ms and collisions are rare-but-possible; without it cursors could skip a row at a page boundary. Cursors are opaque base64url(JSON `{ts, id, order?}`) — never construct them by hand.
- **The document list has TWO orderings, and the cursor knows which (migration 0017).** `order=created` (default) walks `documents.created_at`, newest-published first; `order=updated` walks `documents.updated_at`, most-recently-TOUCHED first — a content write, a classification edit (retag/rename/visibility/status, none of which bump a version), or a revoke all move a row to the top. `updated_since=<ISO-8601>` windows it (`updated_at >= ?`, inclusive so a feed can pass back the newest stamp it saw); the parser **normalizes** it through `Date.parse` → `toISOString()` because the SQL comparison is a lexicographic `>=` against TEXT, which only equals a chronological compare when both sides are D1's exact `YYYY-MM-DDTHH:MM:SS.sssZ` shape. Together they make `list_documents` a change feed. **A cursor carries the ordering that minted it and a mismatch is a hard `bad_cursor`** — reading an `updated_at` cursor under the created ordering compares two unrelated timestamps and silently skips or repeats an arbitrary slice, which a change feed can least afford. An ABSENT `order` on a cursor means the created default, which is what lets the agents/keys/backfill lists mint bare `{ts,id}` cursors untouched; an *unrecognized* one fails the whole decode. Both new params reject with `bad_request` (not a dedicated code) — they're plain parameter-shape rejections with no context field to branch on, matching search's `?mode=`. When you add a new list endpoint, route it through `pagination.ts` rather than introducing a new style.
- **The publication axis is a FILTER pair, and `publication` is the one list filter that excludes revoked rows (migrations 0011 + 0018).** `visibility=public|private` is a plain `d.visibility = ?` equality; `publication=pending|current` is not a column at all but the RELATIONSHIP between `d.published_ver` and `d.current_ver`, emitted by the single `publicationClause()` helper in `core.ts` that the list surface and BOTH search legs share. Composed, `?visibility=public&publication=pending` is the operator's **review queue** — every public doc whose readers are still seeing older bytes — answered in one request instead of the full-corpus walk plus client-side compare a review UI needed before (that walk is what motivated the pair). Four things to keep: (1) the SQL is **null-safe** (`IS` / `IS NOT`, never `=` / `<>`) because `published_ver` is genuinely nullable and `NULL <> 3` is NULL — the plain comparison silently drops every never-published doc out of `pending`, which is most of a private-by-default corpus; (2) both branches carry `d.revoked_at is null`, the deliberate exception to this surface's "filters narrow, revoked rows still appear" rule — revoke nulls BOTH pointers, so a dead row would otherwise satisfy `current` (NULL IS NULL) and claim a publication state it doesn't have; (3) the two filters stay **orthogonal** — no `visibility` term is baked into `publicationClause`, which is what keeps "private docs with staged versions" expressible and makes `visibility=public` the composing knob rather than an implied one; (4) they **narrow, never grant** — every caller is already credentialed and both values have ridden every listing row since their migrations, while flipping visibility and moving the pointer stay operator-only writes on other routes. Reachable on `GET /d`, `GET /admin/documents`, both search doors, and MCP `list_documents` — but deliberately NOT MCP `search_documents`, matching the `updated_since` asymmetry already there. Unknown values reject with `bad_request` (the 0017 precedent for enum params, not a new `ErrorCode`). `test/mcp-errors.test.mjs`'s "no tool declares a visibility input" guard is now keyed PER-TOOL so a read filter on `list_documents` passes while a settable `visibility` on any other tool still fails — don't relax it back to a blanket token scan.
- **Search is hybrid (keyword + semantic), NOT cursor-paginated.** `GET /d/search` (agent-reachable, `requireReader`), the operator `GET /admin/documents/search`, and the MCP `search_documents` tool reuse the filter parser (`parseHttpListParams` / `parseMcpListArgs`) for `tags` / `slug` / `status` / `limit` (plus `updated_since` **and** the `visibility` / `publication` pair on the two HTTP doors — MCP `search_documents` has none of those three), but ignore the cursor field AND `order` — relevance rank (BM25 or the fused RRF score) is not a stable cursor key the way `(created_at, id)` is, and windowing narrows WHICH rows can rank without reordering them. Results are capped at `limit` (default 50, max 200) and the response has no `next_cursor`. A `mode` param (`hybrid` default | `keyword` | `semantic`) selects the legs: `keyword` is FTS-only (today's behavior), `semantic` is vector-only, `hybrid` fuses both via `reciprocalRankFusion` (docs/design/vector-search-design.md §10). **`searchDocumentsCore` now takes the RAW query** (not a pre-tokenized FTS match) — it runs `buildFtsMatchQuery` internally for the keyword leg AND embeds the un-tokenized query for the semantic leg, so the callers no longer pre-tokenize. `bad_query` (422) now fires only when **no leg can run** (keyword mode with no usable tokens, or hybrid/semantic when the embed failed AND there are no tokens) — a tokenizable-but-zero-results query is a legit empty set, not an error. The query embed is best-effort: an AI failure degrades hybrid/semantic to the keyword leg, never a hard error. `matched_field` gains `"semantic"`; `score` scale differs by mode (fused/BM25/cosine), comparable only within one result set.
- **FTS5's `bm25()` takes one weight per column OF THE TABLE — including `UNINDEXED` ones.** This is the single easiest thing to get wrong in `searchDocumentsCore`, and it fails **silently**: an UNINDEXED column still consumes a weight slot, so omitting it shifts every weight one column left and drops the last column onto bm25's `1.0` default. That is exactly what shipped for a while — `20.0` was spent on `document_id` (which can never match), `title` effectively got `5.0`, and `description` and `body` tied at `1.0`, so a description hit and a body hit came back with identical scores in arbitrary order, degrading hybrid's fused ordering too. Nothing errors. `BM25_WEIGHTS` in `core.ts` is therefore keyed in CREATE order with one entry per column (`document_id: 0.0, title: 20.0, description: 5.0, body: 1.0`) and the emitting call lists every one. **`snippet()`'s column indices count the UNINDEXED column too** — the two conventions do NOT differ, contrary to the note still in `migrations/0012_document_tags.sql`. Add a column to `documents_fts` and both argument lists move together.
- **Document filtering** (`tags`, `slug`, `status`, `visibility`, `publication`) lives on the document list/search surfaces — the parser collects them for every endpoint that uses `ParsedListParams`, but only `listDocumentsCore` and `searchDocumentsCore` consult them in SQL (the agents/keys lists silently ignore the fields). `tags` is AND semantics: one `tags LIKE ? ESCAPE '\\'` per requested tag against the JSON-encoded `documents.tags` column (document-level since migration 0012 — the filter never used FTS). The underscore in the tag charset collides with LIKE's `_` wildcard, so `tagLikePattern()` in `core.ts` escapes it with `\_`. Tag inputs are silently sanitized to the stored shape at parse time (matching write-time semantics); slug inputs are validated and reject with `bad_slug` on invalid charset (matching the write-time reject-not-sanitize rule). `findDocumentBySlugCore` is the dedicated single-row lookup behind the `GET /s/:slug` HTTP redirect (it validates the slug via `validateSlugInput` upstream of the DB hit). There is no longer a `find_document_by_slug` MCP tool — the slug-lookup path on MCP is `list_documents` with a `slug` filter (returns 0 or 1 rows; the caller reads `documents[0]`).
- **FTS sync is write-path-local.** No D1 triggers — `publishDocumentCore` / `updateDocumentCore` / `revokeDocumentCore` each include the `documents_fts` INSERT/UPDATE/DELETE in their existing `META.batch()` so the FTS row tracks the document's current version atomically. The body column is the markdown derivation of the sanitized HTML, computed once per write via `htmlToMarkdown(prep.cleanedHtml)`. Since migration 0012 the FTS row indexes only `title`/`description`/`body` — **tags are NOT FTS-indexed** (the `setDocumentTagsCore` mutator and the `?tags=` LIKE filter both touch `documents.tags` directly, so a tag-only write touches no FTS row). The FTS row is the SOLE storage of body-as-text — no `body_text` column on `versions`. If you add a new write surface, mirror the FTS sync inside the batch (or extract a helper) — don't ship a write path that bypasses FTS, or search will silently lag.
- **Link-graph sync is write-path-local too (migration 0016, GitHub issue #40).** `documentLinkStatements` (core.ts) emits the DELETE-then-INSERT `document_links` statements and the publish/update batches splice them in alongside the FTS row (edit/restore ride `updateDocumentCore`; revoke deletes the doc's outbound rows in the revoke batch — the FK cascade never fires because revoke tombstones rather than deletes the `documents` row). Targets are stored RAW (a link may name an unclaimed slug — legal; that's the late binding), self-links are filtered, rows cap at 200/doc, and the multi-row INSERT is chunked under D1's bind limit. Read-time resolution lives in `documentLinksCore` (backlinks = live docs addressing this doc's public_id or CURRENT slug — a link to a since-renamed slug is deliberately NOT a backlink, it reports as `redirected` on the source doc's outbound list; outbound states = `live`/`redirected`/`retired`/`revoked`/`missing`). **Backlinks are credentialed reads, never anonymous** (`GET /d/:id/links` via `requireReader`; MCP `read_document include_links`; the manage page's Link graph panel) — a backlink row is a listing row for ANOTHER (possibly private) doc. Inbound rows pointing at revoked/renamed targets are NOT cleaned up — they resolve to broken states at read time, which IS the broken-link report. - **Operator session cookies + CSRF (`src/session.ts`).** Two cookies, both **host-only** (no `Domain`) and `SameSite=Lax`: `awh_session` (HttpOnly — the signed credential) and `awh_csrf` (readable — delivers the CSRF nonce to the page). `Secure` is **conditional on request protocol AND host** (`isSecureRequest`): always set over https, and also set over plain http to a NON-loopback host — a misconfigured zone (Cloudflare answers port 80 unless "Always Use HTTPS" is on) or an active downgrade must never mint a cleartext-transportable operator session. It is omitted ONLY over loopback http (`localhost` / `127.0.0.1` / `[::1]`), because a blanket `Secure` is silently dropped by the browser on http and would break `wrangler dev`. Accepted consequence: `wrangler dev --ip 0.0.0.0` reached from another device at `http://192.168.x.y:8787` is not loopback, so its login cookie gets `Secure` and is dropped — use `http://localhost:8787` or an https tunnel. CSRF is **stateless signed double-submit**: the nonce lives inside the *signed* session payload, and a cookie-authed mutating request must echo it (`X-CSRF-Token` header for JSON/admin; `csrf_token` form field for the HTML `/login`, `/logout`, `/d/:id/revoke` forms) — the server constant-time-compares the echo to the verified session's nonce, so a cookie-vs-cookie injection can't forge it. The pure crypto/cookie core takes explicit `nowMs`/`operatorToken`/`epoch` (no `Date.now()`, no env) so it's unit-tested in `test/session.test.mjs`; only the thin env wrappers read `env`. Login/logout/revoke set **two** Set-Cookie headers via `headers.append` (not `.set`, which clobbers). `next` redirects are origin-whitelisted via `validateNext` (rejects `//evil.com`, `/\evil.com`, absolute URLs, CRLF). Never log the operator token or the derived signing key (same discipline as the OAuth token / minted keys). **The shared form ladder `authorizeOperatorForm` has THREE rungs**: pasted `operator_token` → synthetic Bearer, CSRF-exempt; else a real `Authorization: Bearer` header → also CSRF-exempt (a bearer header is never ambient — the same reasoning `requireOperator` uses); else session cookie + `csrf_token` field. Rung 2 exists because `requireOperator` accepts that identical header, so rejecting it here 401'd a *successfully authenticated* operator with "sign in or paste the operator token" and forced `OPERATOR_TOKEN` out of the header and into a request body. `handleRevokeForm` and `authorizePostOperator` keep their own two-rung copies (no header Bearer) on purpose.

(2) **Do not bump `wrangler` past `4.107.x` to fix `sharp`.** It looks like the clean upstream answer — `4.114.0` is the first release carrying a patched miniflare — but the `@cloudflare/workers-types` peer moved to **v5** even earlier, at **4.108.0** (bisected during the MCP 2026-07-28 upgrade; an earlier version of this note mis-attributed the move to 4.114), and v5 collides with `agents` → `partyserver` (peers `^4`) and would drag a major types bump through `tsc` for a **dev-scope** CVE that never ships to the Worker. Overriding `sharp` alone is the smaller, verified change. Since `sharp` is native and miniflare pinned it exactly, an override there is the one that can actually break local dev — re-verify with `wrangler dev` + a `/healthz` hit, not just `npm test` (the unit suite never loads miniflare).
- **Secrets** (`HMAC_PEPPER`, `OPERATOR_TOKEN`) live in `.dev.vars` for local dev (gitignored) and `wrangler secret put` for production — never `[vars]` in `wrangler.toml`. `SESSION_EPOCH` is the exception: a non-secret rotation counter, so it lives in `[vars]` (default `"1"`); bump it to invalidate all browser sessions.

The write path runs it as a **cheap pre-screen BEFORE `sanitize()`** to reject depth-bombs (GitHub issue #42) — both `sanitize()` and the precise `maxDomDepth` are ~**O(n²)** in nesting (html5ever tree-build + `RcDom` drop), so a near-byte-cap bomb burned seconds before the `too_deep` 422 could fire. The scan converts markdown first (pulldown-cmark is O(n)), then screens the HTML's open-tag depth ~1000× faster (9 ms vs ~58 s at depth 50k). It keeps a bounded **open-element stack**, so `</name>` pops to its nearest matching open element and an end tag matching nothing open is IGNORED, as the parser ignores it — getting that wrong is what let `<div></foo>` scan as depth 1 while the real parse nests one `<div>` per repeat, re-opening the quadratic path. It's still an **approximate** measure (void/self-closing leaves don't count except inside foreign content; comments + raw-text element content are skipped; quoted attrs handled; the pop search stops at a barrier element or after 32 entries) — every approximation is biased to **OVER-count**, and the two residual under-counts (an inserted `</p>`/`</br>` transient, the implied `html > body`) are constant, non-accumulating, and documented in the module header's exhaustive ledger. The count **saturates at `DEPTH_SCAN_CAP` (513, one past `MAX_DOM_DEPTH`)** and early-returns there, so a bomb costs O(bytes scanned) with a bounded stack — a reported depth of 513 means "at least 513." `DEPTH_SCAN_CAP` must stay **strictly greater** than the caller's reject threshold (equal would saturate at exactly the threshold and pass every bomb); `depth.ts` is a leaf (no core import) so the coupling is a comment plus the optional `cap` parameter. The precise `maxDomDepth` post-`sanitize` check (issue #41) stays the authoritative converter-overflow guard, now always on shallow, pre-screened input. **Two-stage depth gate: cheap approximate pre-scan (perf) + precise post-check (correctness/crash-safety).**
